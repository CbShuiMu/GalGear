## 已核对事实

- 当前导航图标与文字左右排列，侧栏宽度为 176—232px 的响应式范围，窄窗口为 146px。
- 详情顶部封面固定 156／130／112px；资料正文为 12px、最高 150px 内部滚动。资料与位置在左半栏，存档与 CG 在右半栏，编辑卡片在其后。
- 封面预设为 180／200／240px，后台限 160—280px，样式只处理三个预设；任意百分比与 Alt 滚轮尚无完整支持，字体大小也没有设置模型。
- 手动添加没有立即触发资料自动补全；自动扫描补全还要求唯一候选归一化同名，搜索词可能受用户编辑标题影响，与本轮新规则有差距。
- 现有备份用于补丁事务回滚，存档发现与手动路径不等于通用存档备份能力。
- Locale Emulator 与 Magpie 未捆绑；现有外部启动器不能直接代表完整的转区／超分功能。
- 2DFan 资料模型尚未提取原画、声优、脚本、音乐、歌手及人物链接，品牌当前映射为 developer。
- 匿名公开页面核对发现：图 2 对应的 The Motion 版本条目没有真实故事正文，现有代码回退到 SEO 摘要；有正文的其他条目需要保留段落。不能自动借用另一版本的故事内容。原站制作人员和品牌链接是标签检索页，不自行宣称为人物详情页。证据：[The Motion](https://2dfmax.top/subjects/16982)、[图 3 资料页](https://2dfmax.top/subjects/2111)。
- 图 4 游戏 TAG 可从主体 `.subject-tags-inline > a.nexus-tag` 提取，品牌和人员则是 `.subject-meta-list .meta-row dd a.nexus-inline-link`。两者虽然都可能指向原站 `/tags/…`，不能全页按链接前缀混抓。当前游戏资料模型没有网站 TAG 来源、链接或编辑覆盖记录；现有本地自定义标签只有名称。

核对源码：crates/ui/src/lib.rs、web/styles.css、web/bridge.js、src-tauri/src/main.rs、crates/core/src/providers.rs、crates/core/src/saves.rs、crates/core/src/patches.rs。官方工具接入依据见 [Locale Emulator](https://github.com/xupefei/Locale-Emulator) 与 [Magpie](https://github.com/Blinue/Magpie)。本轮不运行或下载这些工具。

## 已确认的新增决策

- Q27：备份只聚焦游戏存档，不纳入整份游戏或 GalGear 配置；详细规则见 Q35—Q37、Q43—Q45。
- Q28：通过 Locale Emulator 以指定区域启动当前游戏，按游戏保存选择，默认日文区域模拟，不修改 Windows 全局区域设置；缺少工具时引导配置。
- Q29：详情为正在运行的游戏提供超分入口，调用用户配置的 Magpie 缩放方案。使用用户安装的 Magpie，游戏未运行时提示先启动，缺少工具或方案时引导配置；实际接入和结果验证仍属于技术验证项。
- Q30：保存品牌、发售日期、原画、声优、脚本、音乐和歌手，以及原站提供的链接。多人名单完整展示，缺失信息不猜测；故事为主阅读区，制作人员为次级信息区。
- Q31（最新修订）：游戏详情右上角只有一个编辑／保存按钮，编辑时下方字段原位变为输入框，统一保存或取消整份草稿；失败保留输入。收藏夹管理及资料关联仍使用居中弹窗。
- Q24：采用图标在上、文字在下的窄导航栏，保留现有顺序及粉色选中态。
- Q25：列表封面和详情海报均随窗口适度增大，再乘用户设定的封面缩放比例；百分比范围由 Q33 确定，实际自适应布局须通过宽窄窗口验证。
- Q26：用户已确认视觉稿：顶部大封面及可编辑标题，正文资料约 2/3、辅助区约 1/3；辅助区依次为编辑配置、游戏位置、存档及正版入口，窄窗口改为单列。故事自然整页滚动。
- Q26 补充：游戏 TAG 抓取、本地缓存和手动编辑作为新增要求；标签卡片置于标题右侧，窄窗口放到标题及操作之后。体系与刷新规则由 Q32、Q42 确定。
- Q32：网站 TAG 合入本地标签体系，统一展示、编辑及筛选，不保留或显示 TAG 来源；不采用来源模型，刷新按 Q42 的本地编辑规则处理。
- Q33：封面三个预设为 90%／100%／120%，默认中档；百分比输入范围 50%—200%，Alt＋滚轮每格调整 5%。100% 是当前窗口的自适应基准；列表与详情共用比例，设置与快捷键同步且持久保存。
- Q34：字体三档为 14／16／18px，默认中档。全界面文字按层级同步调整；标题、按钮、标签和路径允许换行，大字号下不裁字。
- Q35：软件先识别并确认存档位置，无法辨认时才让用户确认或指定。支持多个存档及历史浏览窗口；证据标准、浏览单位与触发由 Q43—Q45 确定。
- Q36：默认备份到应用数据目录，便携版使用 data 内的备份目录；可改目录。每游戏默认保留最近 10 份，可调整数量并锁定重要备份；新备份成功后才清理最旧的未锁定备份。
- Q37：恢复到所选快照的完整存档状态，包括移除快照中不存在的后续文件。恢复前自动备份当前存档，展示覆盖、新增和移除并确认，重新确认实际目标；运行中或状态未知时禁止恢复，失败回滚。
- Q38：普通启动与转区启动合入启动按钮下拉菜单，按游戏保存默认方式，主按钮显示当前方式；超分保留独立入口。
- Q39：Magpie 的算法和倍率等在其自身配置，GalGear 检查工具、定位目标窗口并触发，不自动改写 Magpie 配置；无法确认缩放结果时不显示已超分。
- Q40：新增品牌和制作人员等字段支持手动编辑、清空及逐字段保护。入库／关联时完整缓存，详情先读本地，主动刷新只更新未手动编辑字段；缺少真实故事时显示暂无故事介绍，保留手动填写和更改关联入口。
- Q42：首次抓取导入标签；后续只补新标签，保留已有本地标签，不因网站移除而自动删除本地名称。用户删除或改名的旧名称不自动重新加入，保存本地编辑规则而非来源；提供重置规则入口。
- Q43：配置或引擎证据能明确归属游戏、位置存在且有可读存档时自动确认。仅名称相似的目录仍为候选，交用户确认；未创建或没有存档提示暂无存档，不生成空备份。
- Q44：按游戏条目保存多份备份快照，每次包含该游戏所有已确认存档目录。存档卡片打开历史浏览窗口，列出日期、大小、备注、锁定状态；可浏览快照内文件、恢复、删除或锁定。
- Q45：提供手动备份及默认关闭的游戏退出后自动备份开关；自动备份仅在 GalGear 运行或托盘时执行。备份与恢复都要求明确检测到游戏未运行。
- Q46：点击标签返回游戏库按该标签筛选，清空文字搜索并保留排序；通过编辑标签入口修改。
- Q47：名称不能为空或全为空格；保存失败或输入无效时保留编辑状态及输入并提示原因，成功保存后才退出。简介、日期等字段仍可主动清空。

Q26 原视觉稿已确认；加入标签卡片的视觉修订见 [ui-design-plan.md](ui-design-plan.md)。该记录只确认布局及产品目标，不表示实际功能已完成。

## 决策树与剩余工作

- 布局：窄导航（Q24）、自适应封面（Q25）、主阅读区与辅助区（Q26）；标签卡片位置随新增指令修订。
- 交互：详情统一原位编辑／保存／取消（Q31、Q47）、封面百分比及滚轮（Q33）、字体三档（Q34）、启动整合（Q38）、标签筛选（Q46）。
- 资料：扩展字段与原站链接（Q30）、离线缓存及逐字段编辑保护（Q40）；不将缺失故事或网页摘要混作正文。
- 标签：统一无来源模型（Q32）、只增量补充和人工编辑规则（Q42）；统一重命名／删除继续沿用原基线。
- 存档：只备份存档（Q27）、软件识别优先（Q35、Q43）、快照及历史窗口（Q44）、存储保留（Q36）、完整恢复及回滚（Q37）、手动和退出后自动备份（Q45）。
- 外部工具：转区含义及前提（Q28）、运行游戏的 Magpie 入口（Q29）、配置分工和结果状态（Q39）。
