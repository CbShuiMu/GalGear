# KiriKiri 的自主准备与冷启动验证

通用实现与随附技能不内置单款游戏的路径、AppID、资源密钥、字节偏移或剧情答案，
也不向新的冷启动任务注入以往调查结果。应用提供本轮实际目录、本地配置和原始资源；
DeepSeek 独立选择工具、调查格式、编写解析程序并提交证据。宿主重放证据，不能由
模型自行签发成功。

每轮会在该游戏的工作目录保存自建程序、调查参数、输入身份和审计记录，供本轮
检查及普通重试使用。这些是实际调查产生的游戏专用产物，不是共享实现预置的答案；
下一轮冷启动不会复制它们。

## 存档发现与选择

本地 Steam AppID 配置和库清单可将游戏关联到数字存档目录。手动指定位置优先；
明确配置关联的位置优先于名称猜测，避免其他目录里较新的标题状态覆盖真正的位置。
游戏目录内与游戏名称关联的存档子目录也纳入有界检查。

文件类型由完整原生状态辅助识别：支持未包装、压缩文本流和带 BMP 缩略图的
KiriKiri 序列化数据。剧情状态、选项及全局已读／解锁数据分别处理，不规定某个
扩展名一定是剧情存档。无法完整解析或身份不明确的文件保留为 unknown，由模型调查；
不能因修改时间最新就强迫把 unknown 文件作为唯一目标。

这些分类用于调度，不证明当前剧情节点或玩家实际读过哪些内容。

准备故事简介时，资料标题和用户显示标题优先；缺少精确结果时可查询真实可执行文件
的名称身份，排除通用启动器及引擎入口名。CamelCase 分词和分隔符空格化只能改变
展示形式，不能改变归一化后的身份。返回候选按 URL 去重后必须只有一个精确标题
匹配，读取资料后还会再次核对标题与非空简介，不用模糊搜索的第一项代替确认。

## 字节、结构与剧情语义

- `galgear_structured` 提供有界的完整 TJS 字面量和 PSB v2/v3 数据树读取。PSB 消息
  必须引用树中的实际字段，字符串池中的可读字符串不能直接算对白。
- 公共原生 PSB 解密、普通 MDF 完整帧及 `document.crypto` 已合入并通过发布包检查。
  模型须自行调查并提供显式参数；宿主不提供游戏密钥或解析答案。
  公共解密只恢复完整结构，不能签发消息角色、当前节点或恢复入口。PSB／MDF
  识别仍须保留完整输入和 typed root；归档来源还须核验完整原生成员及其校验和，不能用 `output.view`
  切到字符串池或局部数据绕过核验；公共格式验证不代表已验证新增游戏兼容性。
- 标准字节视图包括切片、解压、重复 XOR 和有界区域 XOR。模型自行调查参数；
  宿主不提供任何游戏的密钥。归档成员过滤还须对照实际 XP3 索引，核对完整成员
  身份、大小和原生校验值，不能只检查解码后的文件头。
- `galgear_codecs.decode("tjs_text_stream", data)` 和同名标准视图提供公开 KiriKiri
  文本流解码：支持带 `FF FE` BOM 的 UTF-16LE 明文，以及 `FE FE` 包装的 mode 0/1/2。
  mode 0 遵循原生读取公式，保留编码端的控制字符，不假定通用编码往返；mode 2 核对
  完整原生长度字段与 zlib 结束边界。输出为去除外层 BOM 的正文 bytes，仍需严格字符
  解码和完整数据语法验证。该 codec 不接受外部密钥、路径、模式或偏移参数；BMP
  缩略图包装须先显式切片，不自动寻找数据。格式依据公开的
  [TextStream 实现](https://github.com/krkrz/krkrz/blob/fd5c4baa6a2ef5978db1bd043634351f48667daf/base/TextStream.cpp)。
- 原生名字经过映射时，可由实际 segment 解压后的完整原始字节唯一确认成员。
  长度相同、文本相似或模型提供的校验值都不能替代这种绑定。
- 完整且边界合法、但尺寸声明与分段表不一致的成员保持隔离，不能签发来源证明；
  其他成员仍逐项验证。隔离成员参与完整字节的身份排歧，不能通过忽略异常项制造唯一匹配。
  截断索引或越界分段仍使整个索引不可采信。
- 对本轮有提取来源记录且来源仍有效的 XP3 输入，宿主可将 `native_archive` 注入
  研究 helper 与正式脚本 parser 的 metadata。完整索引和当前输入的完整原始字节须
  独立绑定，才提供 `adler32`、`size`、`packed`、`flags`、`entry_id`、`index_sha256`。
  `scope="native_declaration_only"` 明确这些只是归档声明，不证明解码成功或当前节点。
  已经由原生工具合法解密的输出可能无法再与 raw segment 相等，此时省略该可选字段；
  不能伪造校验值，也不据此取代后续 `member_filter` 的完整成员验证。其他归档格式和
  loose 文件沿用原有流程，陈旧来源仍须重新提取。
- 代表性脚本需要来自实际剧情资源。系统示例或菜单不能代替故事样本；模型记录
  的资源角色只指导研究，不减少应验证的成员，也不证明说话人或节点。

只读研究采用 advisory 调度：有界的读取、列表和检查，以及精确的 `run_skill`
info/list 命令，不因已读取多次或尚未测试 parser 就被禁止。宿主记录重复读取并建议
在证据足够时进入编写和测试；这些建议不签发证据，也不延长请求次数或运行时限。
实际路径隔离、输入大小、纯解析沙箱、资源选择、完整覆盖、说话人和节点验证仍是
独立约束，准备完成必须通过原有验收。

## 当前台词与恢复入口

已有独立验证的当前台词继续使用 `coverage="node"`。标准公开 KAGParser 的
书签恢复另有 `kag_parser_label_v1` profile：宿主完整索引原始 KS 标签，核对保存
对象的原生 storage 与 label，签发 `coverage="resume_node"`。它证明书签的恢复
入口，不证明最后显示的台词；不从 `curLine` 或 `curPos` 伪造当前对白。

该语义依据公开的 [KAGParser 保存与恢复实现](https://github.com/krkrz/KAGParser/blob/master/KAGParser.cpp)
及 [KAG 主窗口书签实现](https://github.com/krkrz/kag3/blob/master/data/system/MainWindow.tjs)。
替换 scenario loader、书签恢复或使用其他场景框架的游戏，需要另外确认其语义，
不能因为文件扩展名属于 KiriKiri 就套用这个 profile。

恢复入口的摘要候选严格停在入口之前；真实存档历史另按其记录顺序使用。提示中
明确区分恢复入口、已显示文本与推断候选。没有任何可支持剧情的前文时，摘要不编造
事件。只有完整结构关系的 `recorded_node`、场景名或未知选择状态仍不能使准备成功，
也不能将 `recorded_node` 升级为 current 或 resume 证明。
当前、历史与恢复入口的记录角色须按完整原生格式及宿主 canonical 记录分别核验；
把 `typed_field` 换成原始整数跨度、省略 native 声明或补写版本号均不能绕过这些证明。

存档核验版本为 3，脚本核验政策为 3，模型契约仍为 4。存档核验版本 1、2 或无版本的
Python 准备结果撤销存档验证资格及依赖摘要缓存，须按本次实际输入重新核验。
脚本核验版本 1、2 的全部 `rows`、
原生节点声明、姓名与原生作用域、脚本验证状态及依赖的存档验证资格都须重新核验，包括
没有说话人表或全部 `speaker=null` 的旧转录；不能补写版本号或通过缓存升级资格。
程序与 helper 源码、原始资源、研究笔记及引用、批量计划和原始审计继续保留；旧审计不作为新版
验证通过的证明。发布包中的公共 PSB／MDF 能力与脚本、存档核验版本同步；其解码通过
不能替代游戏当前状态、角色语义或完整准备的验证。

准备请求的输出预算根据官方模型能力选择并在截断后有界扩容，保持最大思考强度。
供应商能力读取、凭证处理和截断边界见 [AI 模型能力读取](ai-model-capabilities.md)。

## 每轮从头测试

先用正式 Rust 逻辑生成脱敏输入，不在测试程序中重写某款游戏的文件筛选规则：

```powershell
cargo run -p galgear-core --example ai_cold_inputs --locked -- `
  "$env:APPDATA\com.galgear.desktop\settings.json" 'D:\Games\Example' |
  Set-Content -LiteralPath 'analysis\cold-inputs.json' -Encoding utf8

python scripts/validate-ai-cold.py `
  --inputs 'analysis\cold-inputs.json' `
  --settings "$env:APPDATA\com.galgear.desktop\settings.json" `
  --output 'analysis\new-cold-run'
```

输出目录必须不存在。工具为本轮生成唯一的空工作目录；`cold_start` 拒绝旧的
非空工作目录，并禁止访问其他准备缓存。不会复制解析器、提取台词、研究笔记、
检查点或旧调查结论。单轮内部产生的检查点仅用于保留该轮审计，不会作为下一轮输入。
服务商自身的自动前缀缓存不作为本地准备复用，也不提供已完成的游戏分析结果。

模型运行期间冻结宿主和完整技能包；新增、删除或修改文件都会使本轮验收失败。
原始游戏资源与存档在运行前后核对哈希。凭证只通过标准输入管道传递，不写入计划
或报告。结束后独立重跑本轮新生成的解析器和证据检查；审计不调用模型。

`--plan-only` 仅完成预检，不发模型请求，也不能记为开启成功。真实游戏冷启动、
合成数据的真实模型实验及离线单元测试应分别记录，不能据此宣称未经测试的游戏
已经兼容。
