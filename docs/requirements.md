# GalGear 首版需求

基线日期：2026-10-12。已确认整合日期：2026-10-13；游戏页追加需求于 2026-10-14 经两轮答复定稿。本文作为实现基线，已确认需求不表示已实现或已验收。

本文记录产品要求，不表示功能已经实现。首版范围以本文为准；后续需求变更需同步更新本文件。

## 1. 产品定位与固定约束

- 面向所有 Windows Galgame 玩家，从第一版起公开发布，不以开发者个人游戏库为唯一适用环境。
- 首版正式支持 Windows 10 / 11 x64；其他系统及架构暂不属于正式支持范围。
- 优先级：游戏整理与启动 > 补丁管理。内置 CG／回想解锁整体退出首版。
- Rust 前后端、Tauri 桌面程序；JavaScript 仅承担必要桥接，业务逻辑使用 Rust。
- 保留现有粉色主题及中文、日文、英文界面。
- GalGear 是本地软件，不建立自己的账号系统。
- MIT 开源，通过 GitHub Releases 发布安装包和便携版。
- 首版提供手动检查更新及下载页面入口。

## 2. 游戏库与扫描

- 支持多个游戏库文件夹，仅管理已安装的 Galgame。扫描只收录游戏 EXE；手动添加及重新定位也只接受 EXE，旧缓存中的纯镜像条目不再显示。
- 不考虑游戏压缩包管理。补丁压缩包属于补丁功能，独立处理。
- 缓存游戏库扫描结果，启动时立即展示缓存，不在每次启动时重新全量扫描。
- 启动后后台增量检查，更新新增或变化的条目；提供用户主动触发的全量刷新。
- 游戏身份、已知路径、标签、编辑及关联信息持久保存。
- 添加游戏库后扫描，用户可以手动刷新。
- 扫描在后台进行，逐步显示已识别游戏，提供进度及取消入口。
- 首版以约 1,000 个游戏条目作为性能验收规模；扫描、2DFan 搜索、图片及资料获取不能阻塞界面操作。
- 自动识别之外，支持手动添加、指定启动程序、纠正误识别、排除条目。
- 刷新保留用户编辑、标签及关联信息。
- 文件找不到时标记不可用，保留相关条目与用户数据，并允许重新定位。
- 从列表移除条目和排除误识别项不删除游戏文件。
- 不同语言版、汉化版、重制版分别保留。版本间关联及“同一作品”分组暂缓，可用自定义标签整理。
- 同版本在不同目录中的安装副本各自保留条目，每个条目最多对应一个安装目录，分别保留启动配置、标签和补丁记录。
- 游戏搬迁并重新定位后保留原身份、编辑和记录；发现重复条目时展示差异，由用户确认处理，不静默丢弃用户数据。
- 路径失效的旧条目在游戏名称旁保留红色感叹号，悬停或聚焦显示原因，详情保留完整文字说明；列表不再常驻失效文字或封面类型角标。尚未确认新位置时说明“路径失效，可能已转移”，确认新位置后才显示“已转移”。
- 用户可以手动移除失效或重复的旧条目；只影响列表，不删除游戏文件、存档或补丁备份。
- 提供排除项管理，可查看并取消排除，恢复时保留原编辑信息。
- 提供搜索、排序、自定义标签筛选。
- 一款游戏可以有多个自定义标签；标签只在该游戏详情中修改，不提供全局标签管理、统一重命名／删除或批量标签修改。
- 标签去掉首尾空白，仅英文字母大小写不同的名称视为相同；不同用词保持独立，不做同义词处理。
- 标签编辑只影响当前游戏；在当前游戏中重命名的目标已存在时合并并去重，删除标签只解除当前游戏的该标签，不改变其他游戏。
- 2DFan 游戏条目 TAG 与用户标签合入同一本地体系，统一展示、编辑及筛选，不保留 TAG 来源。来源规则不影响其他资料字段的原站链接。
- 首次抓取导入 TAG；后续只补充新名称，保留已有本地标签，不因网站移除而自动删除。用户删除或改名的旧名称不自动重新加入，记录本地编辑规则并提供重置入口。
- 点击详情标签返回游戏库并按该标签筛选，清空文字搜索且保留排序；修改通过详情页统一编辑模式进行。
- 原添加游戏库按钮位置改为“添加”，弹出“游戏库”和“游戏”两个选项。
- 提供本地游玩状态“想玩／在玩／玩过／搁置／弃坑”，另可清除标记；嵌套收藏夹及交互规则按游戏页追加修订执行；时长统计继续暂缓。

启动缓存、增量更新及联网任务均需保持界面可操作；已有封面直接复用，用户编辑持续优先。

## 3. 2DFan 游戏资料与海报

- 2DFan 是首版游戏资料与海报来源。
- 新入库游戏按游戏文件夹名自动搜索，用户仍可手动修正搜索词。
- 用户可以修正搜索词和资料关联。
- 根据本轮新增指令，搜索结果只有一个时自动关联，不再要求结果名称与本地名称完全一致；多个结果时展示候选，由用户选择。此规则不改变逐字段保护用户修改的要求。
- 保存选定的 2DFan 条目关联，后续访问使用该关联。
- 自动补全名称、封面、简介、开发商 / 发行商、发售日期。
- 扩展缓存品牌、原画、声优、剧本／脚本、音乐、歌手及原站提供的链接，完整保留多人名单；品牌按原站字段保存，不未经确认推断为开发商或发行商。TAG 按第 2 节的无来源本地体系处理。
- 自动补全只更新未被用户编辑的字段；用户编辑过的字段优先保留。
- 首版支持手动编辑名称、简介、开发商／发行商、发售日期及封面，逐字段保护手动修改。名称作为标题须非空；其他允许置空的字段，主动清空也属于受保护的手动修改。
- 每个字段可单独恢复自动获取；重新搜索或更换资料关联仍保留其他字段的手动修改。
- 新增资料字段同样支持手动编辑、清空和逐字段保护。入库／关联时完整缓存，打开详情优先读本地，主动刷新只更新未手动修改字段。
- 故事正文保留段落，原站没有真实故事时显示“暂无故事介绍”，不将通用网页摘要或其他版本的故事冒充该条目正文；保留手动填写和更改关联入口。
- 已有本地海报直接使用，仅在缺失时自动搜索下载；手动指定的海报优先。
- 用户可以主动重新搜索、更换封面。
- 安装游戏的自动海报保存为游戏目录中的 `cover.jpg`。
- 目录不可写时保存到应用数据目录，并显示原因。
- 不覆盖已有同名图片。
- 缺少海报或获取失败时沿用当前粉色花朵、游戏名缩写占位海报。
- 本地结果先展示，联网获取在后台进行；失败显示原因并允许重试。
- 外站不可访问、要求登录或没有结果时，本地管理、查看与启动仍可用。
- 资料与海报保存后可离线使用；不存在 GalGear 自有账号或云同步前提。

## 4. 游戏启动与窗口行为

- 支持按游戏设置启动程序、启动参数、工作目录和外部启动工具，包括 Locale Emulator 等用户已有工具。
- 按 2026-10-14 图 1，详情头部并列提供“启动游戏”“转区启动”“超分”三个入口，取代旧版启动下拉菜单；按游戏保存的区域配置继续适用，普通启动明确使用普通方式。具体工具规则见第 13 节。
- 启动游戏后的行为可选：保持打开、最小化、退出；默认保持打开。
- 关闭主窗口时的行为可选：退出、驻留托盘；默认退出。
- 窗口行为设置持久保存。
- 识别配置启动程序对应的真实游戏进程，覆盖 GalGear 启动、应用外启动及 GalGear 重启后的情况；外部启动工具自身状态不能代替游戏状态。
- 检测到运行时显示“运行中”并阻止重复启动。无法判断时显示“未知”，普通启动允许用户确认后继续，并提供重新检测入口。

## 5. 补丁管理与站点接入

### 5.1 本地补丁

- 首版支持补丁压缩包 ZIP / RAR / 7z，以及 EXE 安装程序。
- ZIP 不依赖额外工具；RAR／7z 依赖本机 7-Zip，缺少时明确提示并提供安装入口，检测到工具后才允许预览和安装。
- 覆盖型补丁由用户选择关联游戏与目标目录，安装前展示待写入文件、冲突情况并确认。
- GalGear 管理的覆盖型补丁在写入前备份，记录安装状态，提供恢复。
- 重叠修改文件的补丁可以在用户确认后安装，涉及重叠文件的撤销按安装顺序逆序进行。
- 恢复前校验当前文件；若用户或其他工具已修改，则停止并说明原因。
- 游戏运行中或状态未知时禁止覆盖型补丁安装和恢复，检测明确未运行后才允许写入。
- 游戏搬迁后保留补丁历史，恢复前必须重新确认目标并校验备份；无法确认时停止，不继续写入旧目录。
- 安装或恢复中断后，下次启动处理未完成操作并保留备份；自动处理同样受运行状态及目标确认规则约束，条件不满足时保留待处理状态并说明原因。
- EXE 补丁提供关联、运行及用户手动记录安装状态。
- 不以 EXE 正常退出推断安装完成；卸载使用补丁自身方式，不承诺 GalGear 对任意 EXE 的文件级恢复。
- 差分补丁暂不列入首版支持。

### 5.2 2DFan

- 2DFan 补丁资源接入为首版必需项。
- 应用内搜索、展示补丁与适用信息。
- 可以直接获取的站内文件由 GalGear 下载；外部网盘资源打开对应网页。
- 支持手动搜索与纠正游戏关联；命中结果不等同于确认适配用户的具体版本。
- 搜索、资料获取、下载认证分别验证，不假定采用同一种凭据。
- 涉及积分或付费时先展示消耗，由用户逐次确认后才提交；无法确定费用或流程时打开原站完成。
- 可以读取时展示账号积分余额，不能读取时显示未知；不以猜测的余额或费用提交购买。真实网站验证结果另记于实现状态文档。

### 5.3 鲲 Gal

- 鲲 Gal 补丁站 `moyu.moe` 接入为首版必需项。
- 应用内展示相关补丁及适用信息。
- 打开原站资源页，由用户自行下载。
- 不要求首版获取鲲站下载直链。
- 具体搜索与资源信息读取方式由公开接口和实际可用流程验证确定。

### 5.4 下载及外站凭据

- 下载到可配置的补丁下载目录。
- 提供进度、取消、失败重试。
- 首版采用单任务下载，退出后停止；重启不恢复未完成任务。持久化下载队列、断点续传和下载历史列表暂缓。
- 取消、失败或重启时清理 GalGear 自己的未完成下载临时文件，保留已完成文件；重启后可通过本地补丁选择器重新选择下载文件。
- 重试前重新检查资源及已购状态，不自动重复领取或扣费；涉及新的付费操作仍需逐次确认。
- 下载完成后由用户选择关联与安装，不自动执行下载内容。
- 覆盖型补丁进入文件预览、冲突检查和备份流程。
- 优先使用无需登录的访问方式；需要时由用户配置自己的外站凭据。
- 凭据保存在本机凭据存储中，提供清除入口。
- token、Cookie 或其他实际凭据类型以接口验证为准，不预设截图中的表单字段就是账号 API token。
- 用户已提供 2DFan 请求截图及更新的凭据供后续测试参考；本文件不包含任何凭据值。

## 6. 内置解锁取消与存档补丁

- 内置 CG／回想解锁整体退出首版，不发布 Angel Tear、AdvHD 等内置解锁能力；相关桌面界面入口及可调用安装命令需清理。
- 既有引擎分析及实验验证属于历史记录，不作为当前支持承诺或首版验收任务。
- 普通全 CG 存档补丁的搜索、下载及安装保留，走文件预览、冲突确认、备份及恢复流程，不承诺自动适配用户的具体游戏版本。

## 7. 数据保存与发布

- 安装版：数据位于当前用户的应用数据目录。
- 便携版：数据位于程序旁的 `data` 目录；移动应用文件夹时保留应用数据。
- 两种版本各自管理设置、封面、标签、手动编辑及游戏关联。
- 路径失效时使用重新定位功能。
- GalGear 配置及游戏库数据的导入导出暂缓；游戏存档的备份及恢复按第 12 节提供，不纳入此暂缓项。
- 游戏资料获取仅向外站发送查询所需名称或资料站 ID；本地业务无需登录 GalGear。
- 安装包与便携版功能相同；运行均需 WebView2 环境。
- 首版手动检查更新、进入发布页面下载，暂不做自动更新。
- 后续构建统一输出 `artifacts/GalGear.exe`，不按每次改动创建不同名称的主程序。安装版与便携版中的主程序也统一为 `GalGear.exe`；发行 ZIP 和安装包可保留版本及发行类型标识。

## 8. 首版发布验收

首版必需：

1. 多库扫描、缓存启动与后台增量更新、已安装游戏管理、手动纠正、搜索排序筛选、标签与启动配置。
2. 2DFan 自动资料及封面获取、歧义候选选择、用户编辑保护、落盘、占位图、离线及失败处理。
3. 本地覆盖型补丁安装、备份、状态、冲突检查、恢复；EXE 关联与运行。
4. 2DFan 应用内补丁搜索及可直取文件下载，外链跳转；鲲 Gal 信息展示及原站跳转。
5. 可配置窗口行为、安装版与便携版数据保存、三语界面、MIT 公开发布、手动更新入口。
6. 约 1,000 个游戏条目的规模验证；网络任务中搜索、滚动、切页和启动操作保持响应。
7. 新导航与详情阅读布局、详情统一原位编辑、添加及启动菜单整合、封面百分比及 Alt 滚轮、三档字体；宽窄窗口及缩放组合不裁字或横向溢出。
8. 自动确认存档位置、存档快照、历史浏览、手动及退出后自动备份、保留锁定、确认恢复及失败回滚。
9. 用户已有 Locale Emulator 的转区启动及 Magpie 的运行游戏窗口超分入口，完成真实接入验证并如实显示结果。

内置 CG／回想解锁整体退出首版；发布前须清理其桌面界面入口与可调用安装命令。普通存档补丁按第 5、6 节验收。

后续范围：游戏压缩包管理不考虑；时长统计、导入导出、差分补丁、自动更新、版本间关联、“同一作品”分组、持久化下载队列、断点续传及下载历史列表暂缓。嵌套收藏夹已追加并定稿，验收场景见游戏页追加访谈文档。

验收要覆盖：缓存启动与刷新、不同游戏库结构、同名不同版本、离线、目录不可写、资料歧义、失效路径、用户编辑保护、补丁文件冲突、EXE 状态、凭据失效、下载费用确认、取消下载、安装中断。

在固定测试机器、发行构建和约 1,000 条目下，窗口可操作后 1 秒内展示缓存列表；扫描或联网期间搜索、滚动、切页响应不超过 200ms。扫描必须显示进度并可取消，总时长实测记录，暂不设统一门槛。验收记录注明测试环境和测量方式，后台任务不妨碍启动操作。

具体场景及现有证据缺口见 [release-checklist.md](release-checklist.md)。本文件记录目标，不表示验收已经通过。

## 9. 事实核实与实现差距

本节依据本地源码核对与既有验证记录，不改变产品目标。本次只更新文档，未修改应用代码、运行应用、测试凭据或提交购买请求；没有重新验证外站当前行为。

- 既有实现记录包含 2DFan 公共搜索、资料与封面下载、有效 Cookie 会话下积分读取、付费领取及已购 ZIP 下载验证。单独的 `authenticity_token` 未能建立认证；更多资源与异常购买场景仍需验收，不据此保证任意资源均可下载。
- 鲲 Gal 当前实现读取公开网页搜索流程，显示原站链接，不取得下载直链；当前查询使用全年龄展示范围。开发者应用密钥与用户登录凭据不可混为一谈。

## 12. 游戏存档备份与历史

- 只备份游戏存档，不备份游戏本体或 GalGear 配置；存档快照与补丁事务备份分别管理。
- 软件先识别并确认存档位置，配置或引擎证据明确归属该游戏、位置存在且有可读存档时自动使用。仅名称相似的目录仍为候选，无法辨认时交给用户确认或指定；未创建或没有存档时提示暂无存档，不生成空备份。
- 按游戏条目保存多份快照，每次包含该游戏所有已确认存档目录。只纳入真实存档内容，不将游戏本体或用户文档根目录当作存档备份。
- 提供手动备份及默认关闭的游戏退出后自动备份开关；自动备份仅在 GalGear 运行或驻留托盘期间检测游戏退出后执行，退出软件后不运行。
- 备份及恢复都要求明确检测到游戏未运行；运行中或状态未知时阻止并提供重新检测及原因。
- 默认保存到应用数据目录，便携版保存到 data 内的备份目录，可更改。每游戏默认保留最近 10 份，可调整数量及锁定重要快照；新快照成功后才清理最旧的未锁定快照，锁定快照不自动删除。
- 存档卡片提供历史浏览窗口，展示快照日期、大小、备注和锁定状态；可浏览快照内文件、恢复、删除或锁定。
- 恢复前自动备份当前存档，重新确认实际目标，展示将覆盖、新增及移除的文件，由用户确认。恢复为所选快照的完整状态，包括移除快照中不存在的后续存档文件；失败回滚。
- 重新定位后保留该条目历史，不盲目恢复到快照中记录的旧绝对路径；按当前确认位置恢复。移除列表条目不自动删除存档备份，历史中的删除动作独立于游戏文件删除。
- 不将未完成或失败的备份列为成功快照，不因失败清理旧备份；备份和恢复过程应在后台保持界面可操作，失败说明原因并允许重试。

## 13. 转区启动与 Magpie 超分

- 转区使用用户已有 Locale Emulator，以指定区域模拟启动当前游戏，按游戏保存选择；区域配置 GUID 留空时默认选择 Run in Japanese (Admin)，手动指定 GUID 时遵从该配置；不修改 Windows 全局区域设置。缺少工具或所需配置时引导配置。
- 保留原启动程序、参数及工作目录要求，实际工具版本、参数优先级及目标程序兼容性需验证；启动工具本身不等同于已启动真实游戏进程。
- 独立超分按钮作用于正在运行的游戏窗口，游戏未运行时提示先启动，工具或方案缺失时引导配置。
- 用户在 Magpie 配置缩放算法和倍率，GalGear 检查工具、定位目标游戏窗口并触发，不自动改写 Magpie 配置。
- 如实区分触发和已确认结果，不能确认实际缩放时不显示“已超分”。接入须通过真实游戏窗口验证，不从静态图或工具进程启动推断成功。
