# 封面去噪与首页 4K 背景

运行 `scripts/setup-waifu2x.ps1` 安装官方 waifu2x-ncnn-vulkan 20250915 Windows 包（约 35 MB）。脚本校验固定 SHA-256，保留随包许可证；`scripts/setup.ps1` 也会调用它。构建安装包时 `tools/waifu2x` 会作为资源打包，无需 Python、CUDA 或云端 API。

应用启动 8 秒后自动检查封面，串行处理，每张之间等待 3 秒。优先处理最近游玩的游戏。CUnet 以降噪级别 1 生成同尺寸封面；4K 背景从原始封面单独执行降噪级别 1 + 超分（`-n 1 -s 2/4/8/...`），最后等比例缩到长边 3840。这样背景生成本身也降噪，同时避免对已去噪封面重复磨皮。原图已达目标尺寸时使用经过降噪的图片等比缩小。竖封面保持竖版，首页沿用现有背景布局；没有封面的游戏保持原状，后续获得封面后自动处理。

最低配置设计目标为笔记本 RTX 2060。所有机器默认使用保守的 128 像素分块、单推理线程、不启用 TTA、Windows 低于正常优先级，不按开发机器的显卡设定更激进的默认值。遇到明确的显存/内存分配错误时逐级降低到 64、32 重试；取消、超时、模型缺失等其他错误不会触发这种重试。扫描中或检测到游戏运行时暂停；推理中启动游戏会在检查后终止当前子进程，空闲后重试。每次推理超过 10 分钟会终止。Windows Job Object 确保应用退出后推理进程也结束。不能保证 GPU 推理完全不占用系统资源，也不能由 RTX 4060 实测推断 RTX 2060 的耗时；仍需在目标机器上验收实际速度和显存峰值。

原图和两个输出均保存在应用数据目录的 `covers/rendered` 内容寻址缓存中。原图保留用于回退；界面与目录中的封面引用切换到去噪版。以源图片 SHA-256、模型版本和参数标识完成记录：`covers/rendered/enhanced/<source>-<pipeline>.json`。当前处理版本为 `waifu2x-20250915-cunet-cover1-background1-long3840-v2`。旧版本仍完整可用时保持显示，只有新版本生成成功才切换；后台从原始源图升级一次。相同封面跨游戏复用，重启和重新扫描不会重复生成；换封面时关联自动失效。

两个输出都经过解码和尺寸校验并原子写入后，才提交完成标记，再原子保存目录。更新前核对游戏仍存在且封面未被用户更换；事件仅更新图片字段。前端先解码两张新图再切换，失败时继续展示旧图。失败原因及 6 小时重试时间保存在同目录的 `.failure.json`，避免无显卡、驱动错误等问题反复重试。

首次离线批处理（必须先关闭 GalGear 和游戏）：

```powershell
cargo run --release -p galgear-core --bin enhance_covers -- "$env:APPDATA/com.galgear.desktop" "$PWD/tools/waifu2x"
```

该命令首次备份 `catalog.before-cover-enhancement.json`，逐张成功保存，失败不替换。再次执行会复用已完成结果。便携模式请传入可执行文件旁的 `data` 目录。

如果 GalGear 正在运行，可加 `--cache-only` 预生成新版本图片和完成标记。该模式不写目录或备份，避免覆盖正在运行的应用数据；启动新版本时会自动采用已完成结果。

已有封面缓存此前被缩略为最多 540×720；超分使用当前缓存的内容，无法恢复真实丢失的文字或画面细节。4K 指输出尺寸，不承诺原生 4K 细节。
