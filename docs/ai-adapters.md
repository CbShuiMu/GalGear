# AI 适配程序与独立证据核验

AI 分析准备分为三层：共享字节能力、模型生成的游戏适配程序、通用证据核验。
新增引擎主要通过适配程序和声明式证据接入，不要求向共用核验器逐个添加引擎布局。
这些层共同验证当前输入；单个字段非空、工具调用成功或解压成功都不等于准备完成。

## 三层的职责

| 层 | 代码与产物 | 职责 |
| --- | --- | --- |
| 共享字节能力 | `bytecodecs.py`、固定的解码工具 | 对原始字节执行有界的 slice、XOR 和已支持的解压；不选择游戏、存档、台词或当前节点 |
| 模型适配程序 | `script_extractor.py`、`save_extractor.py`、配套 metadata helper | 根据实际引擎和版本解释容器、指令、函数、姓名、存档状态，提交原始字节与声明式关系证据 |
| 独立证据核验 | `evidence.py`、`adapter_evidence.py` | 重读原始字段，完整遍历计数表，核对指令操作数、函数作用域、返回地址和唯一台词关联，拒绝无法重放的声明 |

模型负责识别引擎语义，例如一个指令是否显示消息、保存的坐标是否为当前执行状态。
通用核验器检查这些声明所引用的字节和关系，不执行模型提供的“验证函数”，也不把
任意 opcode 声明当作已经独立证明的虚拟机语义。尚未确认的版本、调用约定、控制流
或当前状态选择规则应记录为限制；不能用通用结构校验声称支持所有引擎版本。

## 适配器复用与源码快照

`adapter_library.py` 是固定的随附适配器目录。模型先匹配实际容器与版本，再通过
`engine_adapter_contract` 读取接口和语义 profile；`inspect_engine_adapter` 只返回
原生结构观察，`reuse_engine_adapter` 将匹配的适配器生成为完整的纯 Python 源码，
交给原有 `write_program` 流程保存，随后仍须执行正常的脚本和存档独立核验。

目录仅接受已登记的适配器 ID，不接受模型给出的文件路径、导入模块名、Shell
命令或验证回调。profile 只能是有界 JSON 数据。引擎对象布局和字段语义位于
各自适配器内，共用核验层继续只接受可重放的字段与节点关系证据。

最终的 `script_extractor.py` 和 `save_extractor.py` 是自包含源码快照；不会在
运行时导入可变的适配器库。原有产物 SHA 已绑定实际实现，因此新增另一种引擎
不改变旧解析器行为，也无需让其他游戏重新生成解析器。共享字节解码仍通过
现有 `galgear_codecs` 接口调用。适配器升级后产生不同的源码 SHA，只按原有
依赖规则重新验证使用该新源码的游戏。

## 共享解码能力

适配程序可以 `import galgear_codecs`，调用：

```python
decoded = galgear_codecs.decode(codec, compressed, expected_size=None)
decoded = galgear_codecs.view(original_bytes, steps)
```

`verification_contract(topic="adapter")` 同时返回当前 codec 能力和声明式证据契约。
当前支持 zlib、raw deflate、bz2、lzma 和受固定 Windows 资源工具支持的 ERISA Nemesis。
这些是字节变换能力；宿主仍要求对解码后的字段提交可重放的跨度或标量证据。

单次输入、输出最多 32 MiB，view 最多八步。压缩步骤可声明当前输入 view 内的
`offset`、`length` 与 `size_from:{offset,width,endian}`；ERISA Nemesis 必须提供原生
长度字段 `size_from`。ERISA 工具路径、程序集和命令由宿主固定，适配程序不能传入
文件路径、Shell 命令或解码脚本。各 codec 的实际完整性能力以实现和测试为准；
不能把一种 codec 的 EOF 或尾随数据检查概括为所有压缩格式的共同保证。

未知 codec 返回明确错误。不能让模型生成一段解码结果，再将该结果自身当作原始
字节证据；也不能因为解码失败就推断游戏没有进度存档。

公共原生 PSB 解密、普通 MDF 完整帧和 `document.crypto` 已合入并通过发布包检查。
模型自行调查显式参数；这些公共能力不提供某款游戏的密钥、解析器或当前节点答案，
也不据此宣称某款游戏已经兼容或开启成功。
公共解密只恢复完整原生结构，不能证明消息字段的执行角色、当前节点或恢复入口。
识别 PSB／MDF 时仍须核验完整输入和完整 typed root；归档来源还须核验原生成员及其校验值。
`output.view` 不能切到字符串池或局部数据后绕过这些要求。

### 受限数据字面量

`literal_evidence.py` 提供固定的 `tjs_const` 数据语法及完整 token 跨度，解析到
整个输入 view 的结尾，不运行 TJS。`galgear_literals` 将同一受限能力提供给纯
适配程序；公开树和字段结果是新数据，不能修改后污染独立核验。UTF-16 非 BMP
字符按实际字节长度计算跨度，字符串按原始完整 quoted token 解释转义。

`structured_field` 通过完整 document、对象路径及直接成员选择字段；文本整数
只接受规范 ASCII 十进制 uint64 token。它可用于输入预检和失败诊断，不会自动
获得当前节点资格。尚无已审的文本坐标与状态角色 profile 时，结构化字段不能
混入旧 binary/call_return 路径来宣称节点通过；scene、resume、last-displayed 与
current-node 的区别由引擎适配器负责。未知 profile 继续拒绝成功。

## 两种节点坐标路径

原有直接路径继续支持：存档中的原生来源与位置字段分别证明 `facts.source`、
`facts.line`，台词字段证明 `facts.anchors[0]`。来源允许既有的同词干原生别名规则，
最终来源标识仍须来自已验证台词行。唯一台词同样需要原生来源和坐标证据。

某些运行时保存函数名与调用返回地址，而台词行使用脚本内指令位置。这些坐标不能
直接互换。新路径先由脚本适配程序声明可重放的函数和指令关系，宿主生成原生坐标
索引；存档适配程序再提交 `evidence.node_link`，连接到这一索引中的唯一台词行。

新路径的逻辑为：

1. 完整核验脚本文本表与实际指令操作数，保留空条目和原始索引。
2. 完整遍历原生函数记录表，将函数名与同一记录中的原生地址绑定。
3. 根据原生代码 section 的 tag 和计数长度推导代码基址与 payload 边界。
4. 从已验证的台词指令起点重放一段明确的指令字节与标量字段。
5. 要求其中的文本操作数就是该行已验证的实际操作数地址、宽度、字节序和表索引。
6. 由序列真实结束位置减去代码基址，计算返回地址；不接受模型提供返回地址常数。
7. 将存档中的原生函数名跨度和返回地址标量，与宿主生成的索引进行唯一关联。
8. 核对关联行的来源、位置、原始台词与存档适配程序声明的事实完全一致。

这条路径不按台词唯一性回退选节点，不按第一个、最后一个或最大字节偏移推断当前
状态；相同文本位于多条指令、多个来源或多个作用域时，仍可能明确失败。

## 共享 native profile

脚本适配程序可在输出顶层提供 `native_profiles`，各台词行只引用共享 schema：

```json
{
  "rows": [
    {
      "position": "实际指令坐标，须为整数",
      "text": "由脚本原始字节解码的台词",
      "speaker": null,
      "evidence": {
        "table": "已完整核验的文本表 key",
        "index": "原始字符串索引，须为整数",
        "reference": {
          "base": "代码基址，须为整数",
          "operand_offset": "相对指令起点的实际操作数位置，须为整数",
          "width": 4,
          "endian": "little"
        },
        "native": {"profile": "adapter-selected-profile", "scope_index": "原生函数记录索引，须为整数"}
      }
    }
  ],
  "native_profiles": {"adapter-selected-profile": "根据实际字节生成的共享 schema"},
  "tables": {"已完整核验的文本表 key": "完整文本表 schema"}
}
```

以上为字段形状，包含说明用占位字符串，不能直接作为程序输出。精确可用契约以
`adapter_evidence.CONTRACT` 和 `verification_contract` 工具返回为准。

共享 schema 包含 `kind:"call_return"`、`scope_range`、`sequence`、`text_operand`
和必需的 `code_region`。`scope_range.table` 声明完整函数记录表的 offset、length、
count_width 与有序字段；字段支持具名 uint、具名计数 text 和有界 fixed 字节段。
记录 walk 必须恰好结束于完整表边界。`start_field` 指向原生地址字段，`scope_field`
指向同一记录内的函数名字段；`base` 必须等于已验证指令引用的基址。

运行栈若只保存不带命名空间的方法名，可显式声明
`scope_range.scope_transform={kind:"last_component",separator:"@"}`。宿主先核验
同一记录内完整名称的原始跨度，再按有界标点分隔符计算叶名称；不能提交任意别名
或改用名称子串跨度。投影后的名称和原生返回坐标仍必须唯一关联；不同模块或
作用域投影后重名时继续拒绝，不按台词挑选。未声明投影时保持原始完整名称匹配。

范围终点是完整记录表中下一个严格更大的原生地址；末尾函数使用已核验代码 payload
的终点。所有函数都要求 `code_region`，不能用整个输入文件的剩余长度充当代码边界。
该 section schema 包含原生 header 的 offset、精确 `tag_hex`、length_width 与 endian；
宿主据此读取真实长度并推导 payload 起点。选定函数的起止、指令起点和完整序列均须
落在该 section 范围内。未解释的函数长度字段不能自动替代这些边界。

`sequence.fields` 只支持精确 bytes 和 uint/table_ref，必须在文本操作数前后保留
实际字节，不能包含运行验证代码、任意跳过到目标地址或返回地址常数。共享 profile
不得填写 `scope`、`scope_range.index` 或 `sequence.offset`：宿主从选定函数记录和
已验证台词指令位置推导这些字段。需要不同序列时可使用不同的共享 profile。

共享 schema 只减少重复体积和重复遍历，不提升证据可信度。完整函数表按 schema 和
输入字节身份复用一次 walk；每行的实际指令字节、操作数和边界仍独立核对。

## 宿主生成的 `_native`

只有正常脚本证据核验和 native 关系重放都通过后，宿主才向 canonical dialogue 行
追加 `_native`。其中记录能力版本、作用域、计算所得坐标、台词位置、脚本与 schema
指纹。模型提交的同名字段不会直接进入 canonical dialogue；模型也不能自行签发
已核验记录。

这些哈希用于输入绑定和审计定位，哈希字符串本身不是签名。可信性来自宿主生成
记录、已验证的脚本输入，以及既有 `dialogue.jsonl` 哈希和准备缓存检查。

运行时的存档适配程序收到一份可读写的 metadata 副本；独立核验器使用宿主保留的
原始 metadata。修改副本中的台词、`_native`、说话人或资源信息不能改变核验输入。
同样，纯程序沙箱必须禁止改写导入模块的属性，避免模型程序更改共享 codec 或
标准库函数后影响随后执行的核验。核验不能依赖模型可修改的模块状态。

`facts.source` 保持 canonical 台词来源标识。原生函数名通过 `node_link.scope`
证明，不应伪装成脚本文件名；原生返回地址通过 `node_link.position` 标量证明，
不应把解压长度、文本长度或其他碰巧相等的整数作为当前位置。

## 既有 NXSC 与 WS2 兼容 profile

`engine_profiles.py` 保留已有审计过的 NXSC 当前 caption 布局和局部 WS2
姓名／消息命令链，迁移时保持原有语义和错误消息。它是现有能力的兼容模块，
不是要求每接入一种引擎都手动修改共用核验器的引擎注册表。

NXSC 仍按原始 magic 独立识别并核对 root 当前 caption。原始 source、position、
anchor 必须来自同一条完整计数记录；历史节点、拼接字段、伪造 current 标记、
scene-only 降级、未知 header、未知显示控制符及变换后的原始字段不能绕过检查。
新 `node_link` 明确不能替代该既有 profile。未知格式也不会自动套用 NXSC 布局。

WS2 的局部命令链证明继续保护姓名与旁白的关联。逐脚本的消息 ID 作用域、原始
消息 ordinal、完整翻译表和全章节覆盖要求保持原状。

## 缓存与失败结果

存档验证使用 `save_verification_version=3`，脚本核验政策使用 `script_verification_version=3`，
模型契约仍为 4；公共 PSB／MDF 能力及其完整结构、外层校验限制见上文。
新版包含独立签发的标准 KAG 恢复入口，
不会把未知结构关系升级为当前台词。脚本与存档都按实际验证版本检查旧准备结果；
存档核验版本 1、2 或无版本的 Python 准备结果撤销存档验证资格及依赖摘要缓存，
须按本次实际输入重新核验。原始来源、结构树与 `_native` 由台词哈希及独立验证共同绑定。
脚本核验版本 1、2 的全部 `rows`、
原生节点声明、姓名与原生作用域和脚本验证状态，以及依赖的存档验证资格均须撤销后重新核验；
无外部姓名表或全部 `speaker=null` 也不能例外，不能只清除外部说话人记录而保留旧字符串池。
程序与 helper 源码、原始资源、研究笔记及引用、批量计划和原始审计继续保留，
旧审计不自动继承验证资格。
`recorded_node` 仍只是结构关系，不能升级为 current 或 resume 证明。
详见 [KiriKiri 自主准备与冷启动验证](ai-kirikiri.md)。

实际脚本、程序、台词、资源清单或验证版本变化仍按现有规则使依赖缓存失效。
新增能力不意味着免除这些检查。早于当前独立验证版本的旧产物仍须按原有升级规则
重新核验；不能补写一个版本号将其提升为已通过。当前 catalog 整体指纹也继续参与
检查点兼容判断，无关条目修改的失效范围不因本文改变。

宿主把已扫描的实际资源清单以有界预览和 `work/source-inventory.json` 提供给模型，
路径相对于游戏目录。清单只描述候选文件，不证明加载优先级；资源探索达到门槛后
仍可分页读取该清单，待测试的新解析器仍优先要求测试。

严格目标存档只有 `coverage="node"` 或独立验证签发的 `coverage="resume_node"`
才能正常返回。后者仅适用于已支持的原生恢复 profile，保留空 anchors 并明确其
恢复入口角色；不能把标签行当作对白。当前、历史与恢复入口的记录角色须按完整原生格式及
宿主 canonical 记录分别核验；把 `typed_field` 改为原始整数跨度、省略 native 声明或
补写版本号均不能绕过这些证明。普通空 anchors、`scene_only` 或 `unresolved`
会保留本次测试产物并返回明确错误；此前同目标的原生
关联失败以有界历史诊断保留，直到真正通过节点核验。缓存命中也须重新检查当前
目标要求，不能用先前非目标的限制结果清除目标错误。非目标 scene-only 审计和
既有多样本模式的额外限制继续保留。

全新准备先执行存档预检：`record_save_preflight` 独立重放模型提交的原生文本或
标量字段，并将观察绑定到存档 SHA。`progress_candidate` 只表示可以继续准备，
不表示已验证当前节点。若必须先调查资源密钥、布局或调用结构，可提交
`needs_context`，声明一个缺失事实和包含该存档的精确文件目标；允许有目标的
资源调查和代表脚本测试，但完整脚本批处理前必须重新检查存档。只含标题初始化
状态时应直接提交 `report_unavailable`。未知编码不能当作没有剧情存档的证据。

存档读取和检查优先于普通资源探索门槛，防止“先提取完整剧本才能检查有没有剧情
存档”的循环。已有有效当前节点强于这项预检，因此有效旧缓存不会因缺少新预检
记录而失去离线复用能力。预检依赖的大型归档采用流式 SHA；同一进程中使用文件
身份、大小和修改时间复用依赖指纹，恢复会话时重新计算。它用于调度，不代替
最终资源来源与当前节点的独立核验。

首次完成当前必需存档的有效预检后，按整套路径与内容 SHA 补充一次资源探索额度。
重复提交、重分类或恢复相同字节不会再次补充，也不会清除待测试解析器或取得节点
验证资格。原生关联失败的恢复指引区分缺少宿主节点证明与已证明节点不匹配；后者
要求定向检查坐标解释、profile 和其他同名资源版本，不能靠修改存档值或标题命中
凑出结果。多个原生候选仍按歧义拒绝。

`report_unavailable` 记录没有可用剧情进度、缺少 codec 或格式尚不能核验等失败结果，
保留原生字段观察并关闭本次准备会话，不能使 AI 开关变为已开启。宿主独立核对所引
用字段确实存在且与声明一致；失败原因和引擎状态的解释仍是模型依据证据作出的诊断，
不应把“核对了几个字节字段”等同于通用证明整个目录没有剧情存档。

## 验证与冷启动观察

离线测试应同时覆盖新坐标关系和原有保护：完整表边界、同记录姓名／地址关联、
代码 payload 边界、实际操作数位置、序列结束位置、歧义拒绝、metadata 修改隔离、
模块状态防篡改、NXSC 旧节点和拼接拒绝、WS2 姓名作用域，以及有效缓存离线复用。
源码测试通过后，冻结宿主也须包含并实际加载 codec、adapter evidence 和兼容 profile。
