# ADR 0003：字体面板通过稳定协议接入 Hook 兼容构建

- 状态：已采纳
- 日期：2026-11-06

## 背景

游戏内需要独立的 Rust 面板，提供字体与排版、字符集伪装、已有文字映射和预览。用户要求操作在运行中的游戏生效，删除离线工具，并允许后续更新 Hook 而不重写面板。

SimpleFontHook 当前没有公开的运行时 IPC。其 INI 文件没有热加载协议，原选择器通过进程内配置版本及 NotifyConfigChanged 请求引擎刷新。直接替换官方原版 DLL 无法保证独立面板控制，也无法可靠禁止原 UI 显示。

## 决策

按用户最新确认，恢复之前的兼容构建，并将完整 Rust 面板接入该构建。兼容补丁包括中文字体在日文 Locale Emulator 下的识别与私有内存字体、运行中安装与 Detours 线程登记、KiriKiri 缓存刷新、Artemis/PFS 读取与字号比例。上游原 UI 由消息窗口代替，不注册原 UI 快捷键。

兼容代码集中在 native/font-hook/compat；字体表算法继续调用上游 FontPatcher。字体准备完成后才发布配置，失败保留原配置。字体资源按参数复用，最多保留 64 个私有副本、128 MiB，直到进程退出，避免旧 HFONT 引用悬空。副本只存在内存中。

补丁只作用于全新导出的构建目录，不修改上游检出。脚本核对修改锚点、PFS 替换边界以及未修改文件的 Git blob；adapter.json 明确记录兼容构建和内核修改清单，不再宣称内核完全原样。

Rust 与适配 DLL 使用固定宽度、显式版本、能力握手的协议。加载器在执行 DLL 入口前检查导出标识；不兼容版本直接拒绝。更新脚本获取上游提交并重新构建适配版，面板不依赖上游内部符号、偏移或 UI 控件结构。

不保留离线字体生成、图集导出、启动前注入或“重启后生效”的替代流程。PFS 兼容模块只为运行时 Hook 读取资源，不能导出或改写磁盘资源包；ACK 只表示接受请求，不代表画面已刷新。

## 结果与限制

协议兼容的适配版可独立替换。上游变更触及适配边界时维护通信层或兼容补丁；构建失败保留旧组件。官方原版 DLL 尚不能直接替换为可控后端。

兼容构建不能保证所有游戏支持晚期加载及即时刷新。预览仅用于本地排版参考；未知引擎布局不强制套用缓存调用。未支持的游戏需如实报告能力不足，不能引导用户重启来宣称完成。
