# ADR 0004：按交付目标编排剧情分析

状态：已采用。

## 背景

此前准备流程要求模型开发两份独立解析器并提交脚本、姓名和当前存档节点的严格证明。
即使已安装 Skill 能读取原生结构，结果也仅作为观察，模型仍被阶段门槛引向重写与反复验证。
这种契约适用于长期复用的解析器开发，却扩大了“静态路线图和当前剧情重建”的任务范围。

## 决策

新 `prepare` 使用独立的 Skill 分析循环，直接调用已有读取器、批量查询完整结构，
一次提交路线图与提要。模型选择研究步骤，宿主集中处理路径、只读执行、预算、输入身份、
审计与最终数据结构校验。已有严格解析器及其缓存修复保留原契约。

Skill 读取与模型查询分别运行在有时限的子进程中，游戏数据不作为代码执行。
批量读取按文件报告失败；查询程序只收到所选 JSON 数据，不获得文件系统或进程能力。
模型调用次数和每次网络、工具耗时单独记录，避免把监督中止时间误报为完成时间。

静态结果拥有单独的 schema 和缓存，定位只授予候选或活动字段解码等级。
没有独立坐标核验器时，模型不能自行将位置提升为静态一致。
它们不能升级为实际游戏恢复验证，也不写入旧解析器的验证通过标记。
同一原生结构可服务路线与提要，模型无需重复提取，SVG 仍由本地安全渲染。

路线探索可能读取后续剧情，因此提要使用单独请求。宿主从实际读取结果中匹配存档字幕或
坐标，裁剪到该锚点，再将有界窗口交给模型；路线研究的对话历史不进入提要请求。
已成功解码的最新进度槽位优先于全局书签列表。本轮成功读取按输入内容及规范化参数
复用，避免模型换用等价调用形式时重复解码，且不引入上一轮的研究事实。

未知格式的纯数据解码也经批量读取入口登记，保留原始哈希与程序哈希，并限制为候选证据。
路线可先独立通过校验并写入部分结果，提要失败不丢失该图；正常发布仍要求两项完成。
连续两次无工具回复（中间一次恢复提示）或三次完全相同的失败调用终止本轮并保留诊断，
避免用满请求上限才反馈无法推进。

## 取舍

这会减少为一次分析开发解析器的工作，但新存档变化目前会重新执行分析，尚未复用上轮
脚本研究作为热缓存。静态结果的语义仍依赖模型的证据解释，因此须交付具体范围、失败项和
限制；不以减少耗时为理由虚构分支、补丁优先级或存档执行历史。

后续如需要可靠的持续增量总结，可在实际格式与任务证明其价值后，把已确认的读取方法
提升为可复用适配器，不再要求所有初次分析先完成这项开发。
