# AI前情提要

## 默认 Skill 分析流程

新开启的 AI 分析使用 `skill_analysis.rs` / `analysis_agent.py`。一次任务同时交付
静态流程路线图、前情提要和当前进度。模型读取已安装 GalExtract 文档，直接复用
归档工具和格式读取器；不再把开发两份长期可复用解析器作为本次剧情分析的前提。
旧解析器缓存继续走下文的严格核验与修复入口，两种结果的契约不会互相冒用。

宿主将游戏资源清单和所有发现的存档位置（含配置目录、用户目录与 AppData）一次提供给模型。
`read_resources` 在一个有时限的子进程中批量读取最多 512 个文件，逐文件保留身份、哈希、
成功和失败。`query_data` 对完整已保存结果进行有界的纯 Python 查询，用于汇总原生选项、
跳转、标签、存档字段和邻近台词，避免逐页抄读或重复实现已支持的格式。
未知格式仍可使用原有只读字节探查；文件写入只发生在本次工作目录。

未知格式可以通过 `read_resources(reader="custom", options={source: ...})` 运行纯数据解码函数
`extract(data, metadata)`。完整结果保存在 `value`，原始输入哈希和解码程序哈希由宿主添加，
后续查询与提要定位共用这一登记结果。`options.inspection_ref` 可引用本轮同一输入上成功的
`inspect_data` 程序，宿主重新在受限工作进程执行并登记；依赖外部 `target_script` 的探查不接受此简写。
提要指针使用 `/value/...`。自定义字段只能提供候选定位，不能授予活动状态解码等级。
读取器保留原生编号、空记录和顺序；翻译表与原脚本的语义关联仍须证据，不能凭相似文字推定。
已识别的 Siglus、Artemis、AST 或 PSB 格式不得用自定义程序替代原生读取器。
导入依赖失败属于宿主环境错误，立即结束批量读取并提示修复，不逐个文件重试。
读取路径可直接指向文件；提供目录和文件列表时支持无歧义的目录相对名称，仍校验根目录边界。

路线图依照有证据的流程结构生成，不要求模型逐句重新概括与路线无关的全部台词。
脚本提取范围、解析失败、未解动态跳转及补丁优先级的不确定性随结果保存。
前情提要结合实际存档与相关剧情重建，并保留语气词过滤规则。路线图允许剧透，
前情提要不得加入当前存档边界之后的剧情。

定位等级明确分为 `candidate`（文本或缓存候选）、`decoded_active`（活动字段已解码）
两个等级。静态坐标是否一致可以描述具体比对，但没有独立坐标核验器时不能自授
`static_consistent` 资格。此流程不启动游戏，`runtime_verified` 始终为 false，
不得把这些等级声明为实际加载验证，也不写旧版 `save_verification_version` 通过标记。
本地仍校验输入未变化、来源身份、图结构、证据引用和两部分总结非空；不完整结果不应宣称全覆盖。

结果独立保存在 `<语言>/skill-analysis.json`，路线图由同一 JSON 在本地绘制为
`route-map.html`。`.skill-analysis-*/` 保留本轮完整对话、每次请求耗时、工具事件、
读取结果和查询程序。相同游戏资源、存档和宿主政策可离线复用；存档变化后重新执行分析。
本地绘图将同一目标的多个选项标签分别排列，并按文字高度分配层间距；独立入口从同层
开始布局。此过程不合并或补造模型提交的边，推断关系与证据提示仍然保留。
本模式默认最多 60 次请求、900 秒，单次模型等待最多 120 秒，均受总时限约束。
瞬态网络/服务失败最多重试一次并沿用当前观察，失败等待也写入请求日志并占用预算；
输出截断时该次重试扩大输出空间（最多 32,768 token），不以相同上限重复截断。
余额、鉴权和配置错误不重试。已知格式统一从 `read_resources` 进入，避免不同工具的
观察与提要登记脱节。角色尚未识别时，预读优先尝试已有读取器识别的原生存档头，
不单凭较新的修改时间把配置文件当作进度槽。
连续两次无工具回复时，宿主在一次定向恢复提示后停止；完全相同参数与错误重复三次也停止。
完整对话、具体错误及部分结果保留，不再用重复催促消耗剩余请求额度。
`submit_route` 可以在提要定位前校验并保存 `route-draft.json`，明确标记为部分结果。
`finish_analysis` 也先保存有效路线，再处理提要；后续可以只提交 `save_position` 复用本轮图。
部分路线目前保留在工作目录用于诊断，只有两项均完成才发布正常应用缓存与完成状态。
进入模型循环前，宿主先批量读取最新已识别进度槽位，避免较新的配置文件挤占剧情分析。
该槽位成功解码后，提要必须绑定其中的字段；历史书签或全局已读索引不能替代它。
本轮内以输入路径、内容哈希、规范化读取器及参数复用成功解析，自动识别与等价显式参数
共用结果。冷启动不会导入之前的读取结果；输入内容或参数变化时重新解析。
`query_data` 在子进程直接加载 JSON，并可按根字段投影，避免大型指令树经进程边界反复复制。
小于 18 KiB 的查询结果完整返回，不因列表条目超过预览数量而额外翻页；更大结果保存在本地。
结构化读取结果的 `value` 才是实际数据，`document` 为解码配置；工具回包同时展示数据入口。
对于字面量 AST，除 Skill 的顶层共享文本表外，宿主还将块内 `text/select` 表投影为
`dialogue`、`choice_texts` 和 `block_observations`。原树、命令、语言键和来源指针保留；
投影不执行宏、不证明命令到选项的运行时映射，也不自行认定匿名文本的说话人。
结局节点必须引用实际结束命令、结局标记、片尾转换或明确的本地攻略；最大编号文件不能作为 END 证据。
`select_recap_context` 将实际存档读取结果中的字幕或坐标与脚本记录匹配，宿主裁出终止于
该锚点的最多 24 条记录。提要由一个独立模型请求生成，只收到这份窗口，收不到路线探索
时阅读的后续故事。字幕匹配仍属候选，不会因此证明玩家的阅读历史。匹配失败时不得以
全剧情梗概替代当前提要。纯 JSON 查询入口为 `analyze(documents)`，旧二参数入口仅保留兼容。
提要选择器支持当前轮已读取的原始文件名或源相对路径，无需模型复写哈希 JSON 文件名；
省略存档文件时使用已成功解码的最新进度槽。同名脚本来自不同归档时必须指定明确来源。
字幕匹配仅忽略首尾空白，保留原始字符串和规范化说明；正文内部空白、标点和语言均不模糊替换。
去掉首尾空白后若匹配多条，仍要求消歧；裁剪使用同一匹配规则，防止同块内的后续台词进入提要。
PSB 场景表额外投影 `scene_dialogue`，给出原生 `record_index`、各语言列和原始指针，避免模型
反复猜测多层数组布局。显式字幕字段以 `anchor_hints` 展示，仅提供候选，原始树保持完整。
多版本脚本都被查看时，`scope.script_indexes` 选择实际用于路线的读取批次，
`scope.resource_selection` 说明原版、汉化或补丁选择依据；选项覆盖针对该资源集合检查，
不把查看过的多个版本累计成多处真实选项。缺省仍检查全部批次，无法确认的覆盖优先级须如实声明。
冷启动基准须归档整个 `.galgear-ai-summary` 后运行正式入口，计时包括资源发现、模型请求、
读取、交付校验及本地绘图，监督停止时间不能当作完成耗时。

构建宿主使用 `scripts/build-ai-agent.ps1`，要求带 PyInstaller 的 Python 3.12 或更新版本。
脚本检查默认 `python` 与 Windows `py -3` 的版本；可用 `-PythonExecutable` 显式选择。
随附 Siglus 0.5.7 声明 Python >= 3.12，且使用新版 `hashlib.file_digest`，因此必须验证打包解释器，不能仅以 PyInstaller 成功作为兼容性证明。

## 既有解析器缓存与严格核验

以下说明适用于旧版解析器准备、已有缓存的继续总结及修复，不是新 Skill 分析的阶段门槛。

路线图发送给模型的台词保留每一行正文、人物、来源、位置和原生函数作用域，
不重复发送逐行的脚本 SHA 和字节验证对象。原始已验证台词仍完整保存在本地，
原生分支证据单独提供并校验内容指纹；这种传输精简不抽样或截断全篇剧情。
独立分段最多同时分析四段，按原顺序收集结果后统一合并。某段失败会等待当前
批次结束并停止后续批次，不发布缺少片段的路线图；成功分段沿用既有指纹缓存。
分段笔记以 12 KB 为精简目标，硬上限取当前输入预算的四分之一与 64 KiB 中较小值。
这样能保留中文路线与来源引用，避免仅因略超目标篇幅而反复读取整段脚本；条目数量、
结构、非空字符串、总体预算及全文覆盖检查仍保留；不再额外限制条目数量和单条
长度。省略 uncertainties 时明确补入“未分析不确定性”的限制，不能视为已证明
完整路线。超限错误包含实际字节数和允许上限。
DeepSeek 的结构化分析请求提供 32,768 token 输出空间，避免合法的中文笔记被旧的
8192 token 上限截断；路线输入预算同时预留输出和提示空间。截断内容仍作为失败，
不会写入可复用缓存。

KiriKiri 的通用存档发现、结构验证、标准 KAG 恢复入口和每轮无本地缓存的测试流程，
见 [KiriKiri 自主准备与冷启动验证](ai-kirikiri.md)。

游戏详情页 → 编辑配置 → **AI分析**，与转区、超分并列。首次开启会读取
设置中胶囊按钮选定的 DeepSeek 或 OpenAI 配置，准备游戏专用存档读取程序、
台词和故事介绍；准备成功后才保存开启状态，并通过顶部消息弹窗提示该游戏的
前置准备已完成、功能已开启，离开游戏详情页也会收到提醒。详情页顶部的 **✦ AI前情提要**
按钮打开的弹窗分别显示“前情提要”和“当前进度”。详情页顶部按 **AI前情提要 →
AI路线图 → 编辑** 排列；未完成前置分析时不显示两个 AI 入口。

前置分析成功后，自动将 `dialogue.jsonl` 发给 DeepSeek 分析游戏分支、选择与结局，
生成并保存静态 SVG 路线图。路线图固定使用设置中 DeepSeek 的模型和凭证；不受
当前选定的前情提要提供方影响。完整台词超出单次输入预算时分段分析全部内容，再汇总绘图。
没有明确分支证据的关系会标为推断，不把台词文件的顺序直接当成实际游玩顺序。
路线分段结果提取 `observations` 和 `uncertainties` 两个字段，忽略额外字段。
格式或体积校验失败时，保留原始输入并附上上次回答与具体错误；每个分段最多请求
三次（初次加两次修复）。
有效分段沿用检查点缓存。最终模型只输出有界的 `nodes`、`edges`、`uncertainties`
JSON（最多 64 个节点、128 条边、24 KB），本地负责层级布局、XML 转义和静态 SVG
绘制；回边、循环和断开的证据分别保留，不为布局补造连接。最终图结构同样缓存，
无效引用或格式可局部修复，最多三次请求，不重做已完成的分段分析。

新准备结果附带 `route-evidence.jsonl`，与台词分别分块进入路线分析；源文件、偏移、
哈希、覆盖范围和遗漏计数随证据保留。当前 Cotopha 读取器提供原生函数表及含对白
函数相关的调用字节候选（同函数到同目标的重复调用合并，保留计数与样本位置），尚不提供完整指令边界 CFG、菜单条件或结局语义。候选连接
必须画为虚线；未知引擎明确记录无原生读取器。旧准备缓存缺少此附加文件时仍可
分析台词，并保留分支证据不足的限制。该文件哈希及本地绘图实现参与路线缓存键。

前情提要和路线图共用台词过滤提示。模型在分析时根据上下文略过没有实际含义的重复
感叹、犹豫声和语气词，保留有意义的反应、应答、拒绝及影响剧情或分支的措辞。
发送给模型的原始台词及其证据位置保持完整。

点击 **AI路线图** 使用 Windows 当前默认浏览器打开本地 SVG。已有有效路线图直接
复用，无需再次联网或读取 API 密钥；台词、原生路线证据、界面语言、路线图模型、提示词或绘图实现改变后重新生成。
路线图失败不撤销已成功的前置分析，显示错误后可以再次点击按钮重试。

使用 DeepSeek 时，前置准备开启思考模式，文档、存档预检、资源定位与收尾使用 `low`，
程序编写、验证与说话人检查使用 `high`，实际解析器修复使用 `max`。若模型公布的能力不支持
所选强度，则使用其支持的最高强度。点击 **AI前情提要**
后的剧情分段分析及最终总结使用 `thinking.type=disabled`，不启用思考模式。

两部分都是必需结果，不能用“没有阅读历史”提示替代任一部分，也不能把只展示
当前台词算作总结完成。当前优先级依次是完整可靠地启动并保留脚本、说话人与存档信息，
缩短完成时间，降低成本。没有已读日志时，AI 仍结合存档节点和相关脚本重建
近期剧情，并简短标明推断范围。

准备结果保存在游戏目录的 `.galgear-ai-summary/<界面语言>/`：

| 文件 | 内容 |
| --- | --- |
| `manifest.json` | 游戏、语言、资源清单及准备文件校验值 |
| `save_extractor.py` | 当前选定的 AI 自行编写、直接读取原始存档字节的程序 |
| `script_extractor.py` | 同一 AI 自行编写的脚本台词解析程序 |
| `result.json` / `events.json` | 模型、验证结果、工具调用及程序哈希 |
| `dialogue.jsonl` | 预提取台词，含来源、脚本位置和说话人 `speaker`；覆盖范围以验证记录为准 |
| `background.json` | 已确认的资料源、链接与故事介绍 |
| `latest-save.json` | 上次总结依据的本地存档事实，不作为下次提要的剧情输入 |
| `latest-summary.json` | 最近一次展示的结果 |
| `summaries/<校验值>.json` | 按存档内容和准备资料保存的前情提要 |
| `route-maps/<校验值>.svg` / `.json` | DeepSeek 生成的静态路线图与完整性记录，按游戏、台词、界面语言和模型复用 |
| `analysis/<校验值>.json` | 分段分析检查点，重试时复用已完成的请求 |
| `analysis-invalid/<校验值>.json` | 不合格回答的本地诊断，保留排错但不会作为缓存复用 |
| `.agent-<语言>-<提供方>/conversation.json` | 完整本地准备对话审计，包含原始工具结果；不会整份反复发送 |
| `.agent-<语言>-<提供方>/request-context.json` | 当前实际发送的有界上下文，支持重启后继续复用缓存前缀 |
| `.agent-<语言>-<提供方>/analysis-notes.json` | 模型记录的结构发现、已排除假设、工具证据引用和后续步骤；不视为宿主验证结果 |
| `.agent-<语言>-<提供方>/analysis-ledger.json` | 带 `O1` 等短引用的结构观察、输入校验信息和完整工具记录定位；不复制原始对话或私有推理 |
| `.agent-<语言>-<提供方>/current-blocker.json` | 模型说明的单个结构阻碍、精确探查目标及探查计划；不是验证证据 |
| `.agent-<语言>-<提供方>/tool-results/<校验值>.json` | 超大工具结果和检查点引用的完整输出，按需分页读取 |
| `.agent-<语言>-<提供方>/tool-results/calls.jsonl` | 所有工具调用的精简索引，指向完整参数、分析代码与结果 |
| `.agent-<语言>-<提供方>/sessions/<会话ID>/` | 分会话保留对话、事件与关闭状态；`requests.jsonl` 保存逐请求诊断和服务商返回的 usage |
| `repair-required.json` | 当前存档未通过独立验证的原因；修复成功后随旧准备目录归档 |

每次开启都先检查已有准备文件及验证版本；文件、游戏资源和验证版本未改变时直接复用，不调用 AI、
不重新提取。关闭选项保留这些文件。切换界面语言或安装/修改脚本补丁后，会提示
重新检查资源；成功准备前不会覆盖已有结果。

说话人核验增加独立的版本标记。旧版 Python 准备结果若全部 `speaker=null`，
下次开启时沿用分析检查点补查姓名来源，不能直接作为完整结果复用；已有姓名
字节证据的准备缓存也须满足当前脚本、存档核验版本才能复用；使用原始脚本消息 ID 的外部姓名缓存还必须通过
逐脚本作用域校验（`speaker_verification.scope_version=2`），避免不同章节的同号消息互相套用姓名。
新版确认为旁白或确实没有可核对姓名的结果，
须完成说话人来源检查后才能保存为可复用缓存。

存档核验使用独立的 `save_verification_version=3`。存档核验版本 1、2 或无版本的
Python 准备结果撤销存档验证资格及依赖摘要缓存，须按本次实际输入重新验证，不能
提前命中准备缓存或旧摘要。保留程序与 helper 源码、原始资源、研究笔记及引用和

工具归档中，读取参数指向预览对应的同一层，不把截断的 JSON 字符串当作结构。
已完成脚本准备、当前处理存档时，将完整资源状态移入内容校验归档；当前源码、
失败、笔记引用、实际探查计划和文档读取状态继续保留。重复状态引用同一权威字段，
`public_checkpoint.read_json` 可读取投影前的完整公开快照，各归档字段有精确 JSON Pointer。
每轮进度采用最多 24,000 字节的紧凑投影，完整状态另存本地；新段已包含当前进度时
不再重复追加同一份状态。公开快照压缩和各类源码的独立预算保持不变；传输重试
同样先检查 480,000 字节总上限，超限仍建立新段。
保留完整本地审计和解析产物。当前段内的思考字段保持完整，
不会剪掉字段或拆散工具调用/结果；新段不重放旧段的思考和庞大历史。历史压缩
不增加模型请求、不重置当前总预算，也不改变必需存档、失败样本账本或验证条件。
旧版本保存的完整长历史也会在首次请求前迁移到有界上下文，原记录继续保留。
缓存最终命中率和费用仍以服务商返回及账单为准。

任务成功、失败、取消或预算耗尽时，宿主主动关闭本次 API 会话、HTTP 响应及连接，
然后退出工作进程；超时或进程异常时由上层终止并等待回收。`session.json` 记录
关闭状态、本次请求数、是否使用额外预算及最终失败类别；同一会话的
`sessions/<会话ID>/requests.jsonl` 逐请求记录阶段、HTTP 状态、`finish_reason`、
耗时、输出上限、可用 request ID 和服务商原始 usage（含缓存及 reasoning 扩展字段）。
失败请求即使没有可执行模型回复，也会保留诊断。诊断不保存 Token、请求头、
服务商自由文本错误体、台词或模型私有推理；完整本地对话审计与诊断分开保存。
旧会话在重试前归档，避免只留下最后一次 `session.json`。本地记录保留供审计及
重试，不代表仍有活跃对话。

DeepSeek 准备任务先从官方模型能力接口读取所选模型的实际输出上限。能力可用时，
普通研究阶段从 65,536 token 开始，脚本／存档编写、验证及说话人检查阶段从
131,072 开始，收尾阶段从 12,000 开始；各阶段均不超过服务商公布的上限和
宿主安全上限。能力不可用时，回退到研究／收尾 12,000、编写／验证 32,000，
不将回退值当作已核实的模型能力。同一阶段已提高的额度保存在检查点中，恢复时
仍受本次核实的上限约束。

遇到 `finish_reason=length` 时不执行截断的程序或工具参数。已知能力时，在同一
工作步骤的剩余尝试内按倍增方式扩容，最多达到实际允许的上限；能力未知时最多
进行一次扩容，且不超过 32,000。达到上限后不再以相同额度盲重试，也不将截断
记为引擎不支持。DeepSeek 前置准备请求使用 `thinking=enabled`，按当前阶段选择
思考强度，传输重试沿用该步骤的强度。断点恢复后重新按阶段和模型能力选择，
程序修复使用最高可用强度。完整 reasoning 随工具对话回传。
支持的强度参见 [DeepSeek 官方文档](https://api-docs.deepseek.com/guides/thinking_mode/)。
网络瞬断、超时、HTTP 429 及指定
5xx 错误可有限退避重试；同一步骤最多 **3 次尝试（初次加最多 2 次重试）**，全部
计入当前总预算。认证、计费、请求配置、证书及不可重试协议错误直接报告，避免
无效重跑。缓存命中与实际费用仍以逐请求 usage 和服务商账单为准。

Windows 下，AI 宿主在执行前加入随 GalGear 生命周期管理的进程组。真正退出软件
时统一终止 AI 宿主及其解析、解包工具，等待宿主退出，将未结束的 `session.json`
标记为 `cancelled` / `closed: true`，并禁止启动新的 AI 子进程。主程序被强制结束时，
Windows 也会随进程组句柄关闭而终止这些子进程；这种情况下会话文件可能保留旧状态。
关闭窗口并缩到托盘仍会继续当前任务。退出前保存的检查点保留，重新开启功能时复用。
重试时核对游戏资源、程序、台词和存档内容，未改变的检查点直接复用已完成
步骤；旧版缺少输入校验信息的检查点保留程序及对话，但重新提取并验证资料。
准备协议 v4 要求 AI 在读取技能后调用 `verification_contract`，返回原始字节证据。
研究笔记通过 `record_findings` 单独保存，每条发现必须引用实际工具观察；工具公开的
坐标字段与宿主验证共享同一份结构。部分或全部条目被拒绝时，结果显式包含错误，
已接受条目不会被其他条目的错误抹掉。笔记只是带来源的模型观察，不替代字节核验。
上下文恢复按字段分别压缩，保留当前阶段、实际下一动作、已验证样本、姓名元数据
和 helper 定位；大资源清单单独归档，不再挤掉这些关键字段。过时且已解决的错误
不会重新作为近期阻塞回放。项目记忆保存在本游戏的工作缓存内，清除缓存后的
首次准备不会读入其他会话留下的共享提取记忆。

配套解析 helper 通过实际字节验证后保存为工作文件，批量加载可用 `helper_key`
直接复用代码。新增其他脚本的独立映射不使已验证样本失效；更改同脚本或依赖的
姓名表仍要求重新核验。首个归档脚本样本会独立登记完整同类章节集合，不依赖
模型先发现姓名资源。样本说话人尚未解决时先补查，之后推进完整批处理；修改
解析器后必须立即测试，重复读取历史也计入探索预算。MAX 推理的代码生成阶段
采用上述按模型能力选择的输出预算；实际 usage 仍按服务商返回值记录，输出上限
本身不代表实际消耗。能力来源和安全边界见 [AI 模型能力读取](ai-model-capabilities.md)。

宿主提供独立于模型程序的通用核验器 `evidence.py`：严格解码文本跨度；完整遍历
模型声明的计数型字符串表，保留空记录及未引用记录的编号；重新读取指令操作数，
核对其编号与实际字符串一致。字段顺序、边界、编号或文本有误时，测试直接失败，
错误反馈给模型继续修正。宿主只执行固定的字节与表结构规则，不执行模型生成的
“验证程序”，也不接受模型自报验证成功。支持有界的 slice、短密钥 XOR、zlib
转换；未支持的压缩或格式须明确失败，不能绕过证据检查。

技能 catalog 还可声明 `verification_policy`：先匹配容器头，再按有界 tag/length
规则定位必须核验的计数表正文。宿主只遍历声明式容器，不解码游戏记录或对白。
匹配策略后遇到非法长度、边界或段数上限立即失败；定位到索引表时，模型必须
提供覆盖原表的完整计数结构及实际指令操作数，不能改用若干直接文本跨度来掩盖
跳过空条目、引用错配或重编号。未匹配容器头或旧版没有对应表时不强加该表要求。

归档脚本需先调用 `verify_resource_selection`，按确切脚本文件名检查资源清单中的
归档，发现同名补丁或旧版本后，核对配置中声明的加载顺序与显式优先规则。记录
候选来源、选用来源及配置；不能只因归档名叫 script 就选用它。加载顺序语义仍需
模型依据引擎文档确认，宿主的配置顺序检查不能证明引擎运行时的全部加载行为。

每条台词保留实际显示的说话人姓名；非空姓名需要匹配的字节证据，旁白或无法
确认的说话人用 `null`，禁止猜测。
核验器分别记录脚本内姓名与配套资源姓名的实际覆盖数量；外部姓名必须有独立
核对的姓名字节和台词到姓名的引用证据，不能因为载入了一份文件名列表就宣称
外部映射已经通过验证。
若台词文件未记录姓名，AI 需继续检查原始脚本、人物名表、说话人 ID 对照表和配置，
通过 `load_script_metadata` 从实际配套文件动态解析映射，传给台词解析程序的
`metadata["speaker_resources"][资源key][条目key]`；额外的普通值仅放入 `metadata["resources"]`。
原始脚本的数字消息 ID 必须通过 `target_script` 绑定各自的翻译脚本；每条消息都保留姓名
或实际空姓名字段的旁白证据，不能把缺少映射直接当作旁白。宿主同时拒绝遗漏已验证消息，
并根据归档完整列表检查所有同类型章节是否都已提取。批量资源选择、配套元数据及台词工具
可完成全章节处理。修复续跑使用已验证检查点摘要，其中保留直接映射形状和姓名预览，
减少反复翻阅无效历史记录。这些文件同样记录校验信息；更换配套映射后必须重新
提取台词并验证存档。`result.json` 记录说话人的解析来源类型及已确认的限制。
先检查游戏内的语言版本和补丁，优先选择界面语言的实际台词；没有对应
翻译时回退到原版并在弹窗中说明。中文故事介绍来自 Bangumi 或 2dfan，英文
来自 VNDB；已关联且有介绍的正确语言资料源直接复用，找不到唯一匹配时要求
先完成资料关联，避免附上其他游戏的剧情。

准备时默认只验证宿主指定的最新一份进度存档，不能换容易匹配的旧槽位来通过。
最新目标必须有完整节点证据并通过独立核验。曾测试的进度样本保存在检查点账本中；
重写程序、重新提取或恢复检查点不会抹掉失败样本，但不要求复测全部旧槽位，
非目标槽位的历史失败不阻断准备完成。额外测试的非目标槽位若只能核验场景，
需记录为 `limited_samples`，不能算作完整匹配、不能隐藏限制。设置文件等负例需显式
声明为 control，不能把已失败的进度样本改为 control 隐藏。运行时发现新存档解析失败，
自动带上错误与当前槽位，利用原检查点进行一次修复准备；再失败则保留可重试错误。

点击前情提要后按修改时间选最新进度存档，并计算 SHA-256。即使文件名、大小
和时间戳相同，只要内容变化就会重新分析；内容相同则先于存档解析和 AI 认证
返回本地结果，生成时间保持不变。恢复到曾总结过的存档也能复用对应记录。
API Token 始终留在系统凭据库，不写入游戏目录。

每次新分析先核验当前台词在存档中的字节证据，再唯一定位脚本节点。`line` 必须
对应提取台词的 `position`；直接文本使用其字节偏移，索引型脚本使用有操作数证据
的位置，消息序号型脚本也可使用完整表遍历所核验的 ordinal。坐标均不代表已读顺序。
每个非空节点都必须有存档中的原生来源及位置证据，唯一台词也不能省略。
对已支持的 NXSC 固定头布局，还核对原生当前 caption 与所选完整计数记录一致；
历史记录、拼接字段或空节点降级均不能代替当前节点。当前 caption 仅按已知显示
控制符及空白规则比较，原始文本证据仍精确核验。无法唯一确定当前节点时明确失败，
不能按第一个、最后一个或最大位置猜测。
`facts.source` 必须采用已验证 `metadata["dialogue"]` 行的完整来源标识，原生字节
证据可使用同词干别名。匹配失败时返回来源、位置、锚点及其组合的匹配数量和
具体错误字段，不返回候选值或自动选择节点。`inspect_data(root="save")` 与正式
存档解析接收相同的已验证 `metadata["dialogue"]`，分析本身不算通过验证。
场景标签同样核对存档字节，随后保留在每一阶段请求中。

有存档实际保存、且经过字节核验的 backlog 时，按保存记录顺序提供历史，允许
跨脚本及代码位置倒退。没有 backlog 时，宿主从当前节点的同一来源中，按代码
位置选择当前节点及此前最近的最多 512 条记录，总 JSON 不超过 96,000 字节，
作为相关脚本候选。它们是真实脚本文本，不是已证明执行或阅读过的路线；宿主
不把整个编译模块的物理前缀当作已读剧情，也不混入其他来源或当前位置之后的代码。

缺少历史仍调用 AI，同时生成实质性的前情提要与当前进度。每轮分析都保留当前
存档场景、精确台词、已验证说话人，以及输入预算内最近最多 32 条原文。模型
优先依据这些近期内容重建人物处境；较远候选只有与近期事件、参与者或引用
相互印证时才用于补充，不能将整个窗口串成玩家已走过的路线。推断的前情简短
标注“根据脚本推断”，分支、身份和完成度证据不足时明确限制。`speaker=null`
时不得凭空归属主角或其他人物；仅有一句时分析该句体现的处境，不编造早前事件。

较长上下文按最多 48,000 字节分段，每段最多 24 条事件观察与 8 条不确定性，
按输入预算进一步限制笔记体积。候选脚本与真实历史使用不同字段和提示语，
分段及合并阶段都保留当前节点和上下文限制。最终请求保留近期原文及当前场景；
笔记过长时分层合并，保留事件、因果与人物状态。格式修复同时提供上一次回答，
避免重新生成时把已有的有效事实丢掉。
中间笔记优先要求字符串项；模型返回含非空字符串字段的对象时，将整个对象
规范化为 JSON 字符串，完整保留来源、位置及其他字段。空对象、没有有效字符串
的对象，以及 null、数字或数组项仍拒绝，规范化后继续校验数量、每项 2,000 字节
和总预算。最终 `recap/current_progress` 仍严格要求两个字符串，不能用对象替代。
作品简介、原始存档变量和上次存档事实也不进入提要请求，避免简介、全局标记
以及回退存档前的较远进度泄露后续剧情。模型须仅依据提供的前文，不补充作品知识。
脚本位置可能是引擎字节码偏移，不等同于阅读百分比；不根据全局解锁或已读标记
推断实际阅读历史。无法确认的分支、章节和完成度明确标为未知。

AI 返回格式固定为 JSON，并校验必填字段和长度：

```json
{
  "recap": "前情提要正文",
  "current_progress": "当前已确认的分支、章节或场景，以及无法确认的进度"
}
```

提要返回的格式、字段或长度不合规，或任一部分只是缺少历史、进度未知等占位
提示时，格式校正流程最多尝试 3 次。该检查能拒绝旧版停用式回复，不能替代
剧情事实审核。允许完整包裹 JSON 的代码围栏；不从说明文字中截取便利片段，
不补造缺失字段。认证、权限和计费错误（401、403、402）直接报告；可重试的
网络瞬断、超时、429 及指定 5xx 最多 3 次尝试并短暂退避，截断不盲目重放。

通过结构校验的分段笔记按模型、提示和输入内容缓存，重试可复用已完成分析；
无效 JSON 或只有占位提示的最终摘要不缓存，可另存至 `analysis-invalid` 供本地
排错但不再回传复用。最终摘要缓存包含提供方、用户
选择的模型及 `context.rs`、`report.rs` 指纹，切换模型或修改候选选择、提示
逻辑后不会继续命中旧摘要；相同配置和内容仍可离线复用。

新读取程序在独立的受限 Python 子进程内运行，有 AST 白名单、45 秒执行时限和
768 MiB 内存上限，只能处理宿主传入的字节与台词，不能访问文件、网络、进程
或 Token。安装包自带运行宿主，不要求玩家安装 Python。当前准备清单版本为 5、
模型契约为 4，提要缓存版本为 5，使旧的本地 `current_only` 展示和旧模型摘要
失效。准备清单和模型契约保持不变，存档验证版本单独为 3，脚本核验政策为 3；只有通过
当前版本检查的 Python 准备产物和摘要可以复用。公共 PSB／MDF 能力已同步打包，
解码通过不能替代完整准备验证。验证升级保留脚本研究和源码，旧产物不能直接
证明新版节点验证通过。提要仍按模型、
提示、输入及准备资料指纹决定能否复用。资源提取和 AI 网络调用在后台
线程运行；同一游戏同时只允许一个准备或总结任务。引擎不支持、台词无法匹配、
存档正在变化、AI 返回无效或不完整时显示可重试错误，不保存伪造进度。

### 离线交互路线图

默认 Skill 分析输出单文件 `route-map.html`：固定的原生 HTML/CSS/JS/SVG 视图由 core
内嵌 `web/route-map.*`，数据以安全转义的 JSON 嵌入；不执行模型生成的代码，也不访问网络。
这些视图源文件仅供 core 打包，不需加入 `build-frontend.ps1` 的桌面静态文件复制清单。
旧解析器缓存仍保留 SVG 输出，默认浏览器入口同时支持两种格式。

DeepSeek 每条选项输出独立原文边，共用稳定节点 ID。同文案在不同脚本位置发生时仍是不同决策点；
已知选择表按输入文件和块位置去重计数，交付时防止合并成选项群。普通线性场景连续超过
八个时要求压缩，不能借此删除选择或结局。边可携带 `pc`、`kind` 与 `condition`；
工具 schema 与交付约束同步公开 EXTRA、GRAND、解锁出处及排除菜单结构，避免只在提示词中要求而在工具中遗漏。
普通剧情节点不能仅以脚本标识符/文件范围命名；缺少官方章节名时，批量读取对白后概括剧情标题，文件坐标仍留在 `pc`/证据中。
合并线性段落时删除段内连线，不能转成虚假的自环；自引用只接受有脚本依据的实际回跳。
带条件的分流单独作为判定节点，分支后续剧情放在对应分支下，避免把某一结局专属剧情概括成所有路线必经的片段。
提交须说明执行顺序来自脚本调用/跳转、本地攻略还是尚未解决的推断，不能把场景名称表当成控制流；当前存档标记必须从故事入口可达。
结构化读取会投影 `selects` 表，保留各语言原文、禁用状态、条件、赋值与目标坐标。
批量返回包含全批次的选择来源摘要；已有明确目标和原文的可用项，交付时不能用“原文未解码”占位。
禁用且没有目标的同名选项不能借用可用项的目标生成路线；其出现条件放在对应可用选项的条件或证据中。
`unlock` 必须说明前置条件并附成功观察的脚本/本地攻略出处，不能把推测解锁当作已知关系；EXTRA/GRAND 使用独立节点类型。主图使用剧情标题，脚本证据在点击
详情中显示。默认检查目标存在性和开始入口可达性；无法证明可达的内容保留并列出警告，不补造边。

DOM 先测量文字，再递归测量展开子树；合流和回跳只保留一个完整子树，其余为可定位的引用按钮。
支持折叠时保持点击位置、全部展开、适应宽度、缩放、鼠标/触摸拖动、键盘和明暗主题。
窄屏默认只展开两层。`scripts/check-route-map.js` 在浏览器上下文检查实际节点/标签不重叠、
输入边不遗漏、折叠锚点、引用焦点和离线性。
