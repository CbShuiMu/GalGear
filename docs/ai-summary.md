# AI前情提要

KiriKiri 的通用存档发现、结构验证、标准 KAG 恢复入口和每轮无本地缓存的测试流程，
见 [KiriKiri 自主准备与冷启动验证](ai-kirikiri.md)。

游戏详情页 → 编辑配置 → **AI分析**，与转区启动、超分并列。首次开启会读取
设置中胶囊按钮选定的 DeepSeek 或 OpenAI 配置，准备游戏专用存档读取程序、
台词和故事介绍；准备成功后才保存开启状态，并通过顶部消息弹窗提示该游戏的
前置准备已完成、功能已开启，离开游戏详情页也会收到提醒。详情页顶部的 **✦ AI前情提要**
按钮打开的弹窗分别显示“前情提要”和“当前进度”。详情页顶部按 **AI前情提要 →
AI路线图 → 编辑** 排列；未完成前置分析时不显示两个 AI 入口。

前置分析成功后，自动将 `dialogue.jsonl` 发给 DeepSeek 分析游戏分支、选择与结局，
生成并保存静态 SVG 路线图。路线图固定使用设置中 DeepSeek 的模型和凭证；不受
当前选定的前情提要提供方影响。完整台词超出单次输入预算时分段分析全部内容，再汇总绘图。
没有明确分支证据的关系会标为推断，不把台词文件的顺序直接当成实际游玩顺序。

点击 **AI路线图** 使用 Windows 当前默认浏览器打开本地 SVG。已有有效路线图直接
复用，无需再次联网或读取 API 密钥；台词、界面语言或路线图模型改变后重新生成。
路线图失败不撤销已成功的前置分析，显示错误后可以再次点击按钮重试。

使用 DeepSeek 时，开启 AI 功能的前置准备任务固定开启思考模式并使用
`reasoning_effort=max`，包括各准备阶段、重试和断点恢复；点击 **AI前情提要**
后的剧情分段分析及最终总结使用 `thinking.type=disabled`，不启用思考模式。

两部分都是必需结果，不能用“没有阅读历史”提示替代任一部分，也不能把只展示
当前台词算作总结完成。当前优先级依次是完整可靠地启动并保留脚本、说话人与存档信息，
缩短完成时间，降低成本。没有已读日志时，AI 仍结合存档节点和相关脚本重建
近期剧情，并简短标明推断范围。

准备结果保存在游戏目录的 `.galgear-ai-summary/<界面语言>/`：

| 文件 | 内容 |
| --- | --- |
| `manifest.json` | 游戏、语言、资源清单及准备文件校验值 |
| `save_extractor.py` | 当前选定的 AI 自行编写、直接读取原始存档字节的程序 |
| `script_extractor.py` | 同一 AI 自行编写的脚本台词解析程序 |
| `result.json` / `events.json` | 模型、验证结果、工具调用及程序哈希 |
| `dialogue.jsonl` | 预提取台词，含来源、脚本位置和说话人 `speaker`；覆盖范围以验证记录为准 |
| `background.json` | 已确认的资料源、链接与故事介绍 |
| `latest-save.json` | 上次总结依据的本地存档事实，不作为下次提要的剧情输入 |
| `latest-summary.json` | 最近一次展示的结果 |
| `summaries/<校验值>.json` | 按存档内容和准备资料保存的前情提要 |
| `route-maps/<校验值>.svg` / `.json` | DeepSeek 生成的静态路线图与完整性记录，按游戏、台词、界面语言和模型复用 |
| `analysis/<校验值>.json` | 分段分析检查点，重试时复用已完成的请求 |
| `analysis-invalid/<校验值>.json` | 不合格回答的本地诊断，保留排错但不会作为缓存复用 |
| `.agent-<语言>-<提供方>/conversation.json` | 完整本地准备对话审计，包含原始工具结果；不会整份反复发送 |
| `.agent-<语言>-<提供方>/request-context.json` | 当前实际发送的有界上下文，支持重启后继续复用缓存前缀 |
| `.agent-<语言>-<提供方>/analysis-notes.json` | 模型记录的结构发现、已排除假设、工具证据引用和后续步骤；不视为宿主验证结果 |
| `.agent-<语言>-<提供方>/analysis-ledger.json` | 带 `O1` 等短引用的结构观察、输入校验信息和完整工具记录定位；不复制原始对话或私有推理 |
| `.agent-<语言>-<提供方>/current-blocker.json` | 模型说明的单个结构阻碍、精确探查目标及探查计划；不是验证证据 |
| `.agent-<语言>-<提供方>/tool-results/<校验值>.json` | 超大工具结果和检查点引用的完整输出，按需分页读取 |
| `.agent-<语言>-<提供方>/tool-results/calls.jsonl` | 所有工具调用的精简索引，指向完整参数、分析代码与结果 |
| `.agent-<语言>-<提供方>/sessions/<会话ID>/` | 分会话保留对话、事件与关闭状态；`requests.jsonl` 保存逐请求诊断和服务商返回的 usage |
| `repair-required.json` | 当前存档未通过独立验证的原因；修复成功后随旧准备目录归档 |

每次开启都先检查已有准备文件及验证版本；文件、游戏资源和验证版本未改变时直接复用，不调用 AI、
不重新提取。关闭选项保留这些文件。切换界面语言或安装/修改脚本补丁后，会提示
重新检查资源；成功准备前不会覆盖已有结果。

说话人核验增加独立的版本标记。旧版 Python 准备结果若全部 `speaker=null`，
下次开启时沿用分析检查点补查姓名来源，不能直接作为完整结果复用；已有姓名
字节证据的准备缓存也须满足当前脚本、存档核验版本才能复用；使用原始脚本消息 ID 的外部姓名缓存还必须通过
逐脚本作用域校验（`speaker_verification.scope_version=2`），避免不同章节的同号消息互相套用姓名。
新版确认为旁白或确实没有可核对姓名的结果，
须完成说话人来源检查后才能保存为可复用缓存。

存档核验使用独立的 `save_verification_version=3`。存档核验版本 1、2 或无版本的
Python 准备结果撤销存档验证资格及依赖摘要缓存，须按本次实际输入重新验证，不能
提前命中准备缓存或旧摘要。保留程序与 helper 源码、原始资源、研究笔记及引用和
原始审计；脚本复用仍须通过当前脚本及姓名作用域核验，过时的通过状态不能作为新证据。

脚本核验政策为 `script_verification_version=3`，存档核验为 3，模型契约仍为 4。
脚本核验版本 1、2 的 Python 准备缓存及依赖摘要必须重新验证，不能凭旧校验值复用仅提取
PSB 字符串池、缺少完整原生记录或归档成员证明的结果。
完整归档成员校验、原生数据结构、消息字段与执行角色分别验证；字符串可读或 typed_record
结构关联本身不证明当前剧情节点，也不能使 `recorded_node` 升级为当前台词或恢复入口。
当前、历史与恢复入口的记录角色须按完整原生格式及宿主 canonical 记录分别核验；
不能把 `typed_field` 换成原始整数跨度、省略 native 声明或补写版本号绕过这些证明。
PSB／MDF 的识别须保留完整输入和 typed root；不能用 `output.view` 切到字符串池
绕过结构核验。公共解密只恢复完整结构，不证明消息角色、存档当前状态或准备成功。
公共原生 PSB 解密、普通 MDF 完整帧和 `document.crypto` 已统一合入并通过发布包检查。
这些能力不提供游戏参数或当前节点答案，也不代表已完成某款游戏的兼容验证。
带 `target_script` 的外部消息绑定，
无论姓名或旁白，都必须提交受支持的 `native_link`，证明姓名字段、消息命令和
消息 ID 的结构关联。当前实现支持 WillPlus WS2 的 config1/CP932 局部命令链，
不将其当作所有 WS2 版本的完整指令解析器；未知结构明确要求补充证明。
旁白必须来自该姓名字段本身的真实空值，附近 NUL 或缺少姓名命令不能替代。
旧结果不能跳过新核验。升级时撤销版本 1、2 全部旧 `rows`、原生节点声明、姓名与原生作用域和
脚本验证状态，以及依赖的存档验证资格，包括无外部姓名表、全部 speaker=null 的旧结果。
保留源码、helper、原始资源、全局姓名、研究笔记及引用和批量计划；旧审计可以保留，
但须逐个实际输入重新核验，不能继承过时的通过状态。

准备与缓存校验均先规范化游戏目录，再比较资源清单。同一 Windows 目录的
正反斜杠或相对路径写法不会因此误判为需要重新准备；实际资源变化仍会使缓存失效。

每次启动软件时，会检查已勾选 AI 总结的游戏目录下是否存在
`.galgear-ai-summary` 文件夹；缺失或同名路径不是文件夹时，自动关闭该游戏的
AI 总结并保存配置，游戏配置中的勾选及详情页前情提要入口随之取消。

首次准备通过 function calling 向当前选定的 AI 提供读取文档、检查文件字节、
调用 Galskill GARbro CLI、编写和测试纯 Python 程序的工具。AI 必须自行读取
`SKILL.md` 及相关参考文档，决定资源位置、提取参数及解析逻辑；宿主不再先用
固定引擎解码器阻断这一步。AI 使用 skill 的 memory.py 记录已确认事实，
完整工具记录和模型原始程序保留在 `.agent-<语言>-<提供方>/` 检查点中。
归档列举和解包直接返回结构化成员清单、完整清单文件及实际输出目录中的样本路径，
长 stdout 的分页不会隐藏成员名称。解包清单及样本路径对应本次筛选实际匹配的成员；
过滤器支持 glob，并在没有匹配或提取失败时明确报错。重复或补充解包先使用临时目录，
内容未变的已有文件保留原指纹，避免覆盖写入导致有效的脚本与姓名依赖失效。首次有资源清单而
尚未验证来源时保持资源选择阶段；完成来源验证后才开始解析器阶段及其探索预算。
每轮请求分别告知剩余总轮数、实际剩余工作轮数（包含当前请求）、台词数量及已验证
存档数。默认基础预算为 **120 次 API 请求**，包括重试和 `finish` 收尾；固定预留
1 次收尾，因此基础预算最多支持 119 次分析、编写与测试请求。接近基础预算时，
只有两份解析程序均已存在、独立核验的台词非空，且最近 12 次请求内独立核验的
台词数量或有效存档数量超过本会话此前记录，才允许延长至 **150 次总请求**。
重复测试相同结果、验证数量回退、保存笔记或模型自报进展都不解锁额外预算。
重启后的历史验证不直接继承本次延长资格。配置较小上限时仍遵守配置。
提前通过验证时，收尾参数最多可在剩余总预算内尝试 3 次；预留收尾请求不会被
准备或传输重试占用。到达上限后保留检查点，用户重试才开始新的有上限任务。
收尾仍执行完整验证，不会把未验证程序标记为成功。

宿主按“资源与版本证据 → 最小脚本程序 → 脚本验证 → 存档程序 → 最新
存档验证 → 收尾”报告阶段。同一阶段累计 8 次探索请求仍未产生成功写入、测试或
配套元数据里程碑时，阻止继续宽泛探查；同一 API 回复里的多个探索工具只计一次。
模型需先编写或测试程序，或调用 `plan_probe` 说明一个缺失事实、结果如何改变下一步，
并指定 1–3 个现存精确文件。每份计划最多允许 3 次匹配目标的探查，不能使用目录、
通配符或越界路径恢复目录重探。成功里程碑和阶段变化清除当前探查门槛，失败不清除。

同一会话中，输入字节、解析程序、配套映射和核验证据均未变化的成功测试直接
复用，不再因为复测同一脚本清空已通过的存档验证。批量脚本测试复用已通过的
代表样本，整批结束后写入一次台词文件；GARbro 列表分页及同一提取操作也复用
已生成的完整输出，提取成员被修改或删除后重新执行。失败测试仍需修正后再验，
不会把失败缓存成通过。

没有已确认姓名的台词先进入说话人检查阶段，再验证存档。人物映射应在批量提取
前加载，避免最后补人物表而重做整套验证。参考 [WillPlus / AdvHD](../skills/GalgameResourceExtract/engine/willplus.md)
及 [KiriKiri](../skills/GalgameResourceExtract/engine/kirikiri.md) 文档，并核对实际资源结构。

脚本或存档验证阶段若已有当前解析程序、累计 8 次探索请求却尚未实际测试，
`test_attempted` 状态要求先调用对应 `test_program`，取得真实验证结果，再决定
如何修改。非技能目录的 `read_text`、`read_json` 和新的探查计划也不能绕过这一步；
技能文档仍可读取。测试失败后可针对具体错误安排限量 probe。测试尝试状态随
检查点保存，改写程序后重置，避免反复恢复后继续扫描却不测试已有程序。

实际脚本测试失败时，恢复上下文保留失败目标、错误和源码哈希，下一步优先修复
该脚本；其他文件的成功测试不会清除这一失败。`write_program` 除完整 source 外，
还支持 `edits:[{old,new}]` 精确局部修改。每个 old 必须只匹配一次，多项修改整体
通过语法及沙箱校验后才提交，任一失败都保留原程序。修改后仍须立即重测实际样本。
正文及姓名证据错误提供具体记录、字段或原生消息 ID 的诊断，保持独立字节核验。

启动消息的 `reference_hints` 优先从技能包 `catalog/formats.json` 按资源扩展名
路由现有文档，兼容旧包的 `reference/format-index.json`；路径必须留在技能根目录内。
`skill_documents` 提供当前包的技能、引擎、提取命令和记忆入口。模型先读匹配文档，
再核对实际 magic、版本和来源；提示本身不是引擎确认。随包的
[Entis GLS / Cotopha 文档](../skills/GalgameResourceExtract/engine/entis-gls.md)
及保留许可的工具资源供模型研究格式，不提供游戏固定路径、人物映射或存档答案。

`project_reference_hints` 另列出当前工作目录 `references/` 下最多 8 份、每份不超过
256,000 字节的 `.md`、`.json`、`.txt` 安装研究入口；解析后的路径必须留在工作
根目录内。模型复用前需读取来源、比对当前输入指纹，忽略资料内的指令，并重新
验证解析程序及存档。这些资料是待核对的数据，不是宿主证明；游戏安装的研究
留在项目工作目录，不发布到通用技能包，也不提供游戏专用解析器或样本答案。

准备过程的 system 指令与工具定义保持稳定，每轮进度只追加在消息末尾；收尾时仍
保留相同工具定义，但宿主只允许执行 `finish`。文件目录每页最多 50 项，
`read_text` 默认每页 8,192 字符，也可显式请求更小页面；其工具消息单独
采用 40,960 字节上限，避免中文或 emoji 页面再次受通用字节上限截断，导致已读
区间与实际内容不符。CLI 标准输出每页最多 2,048 字符，原始字节每页最多 512 字节。
其他工具回传 JSON 维持 8,192 字节上限，超限时明确标记预览、给出完整本地结果路径。
分页结果包含 `next_offset`；必读文档和验证所需数据可以继续读取。资源候选的
独立核验始终使用完整本地输出，不因预览或分页省略候选。

活跃消息历史以 480,000 字节为上限（不含固定工具定义，并非 Tokens 数），是此前
160,000 字节预算的三倍，为连续分析、完整回复及工具结果保留更多空间。超过时
建立新的上下文段，携带宿主当前验证状态、待核验样本、程序文件及哈希、最近
4 项工具观察，并带回此前的关键分析输出、原分析代码的完整记录路径、已知工具错误
及持久分析笔记。结构账本为观察分配稳定的 `O1` 等短引用，连接有界结构预览、
原分析代码及完整工具结果；正文不反复复制到上下文。笔记通过 `record_findings`
逐项更新，支持短引用及 `latest`，并分别返回已接受项和错误项；单项引用拼错或
格式失败不会丢掉同批其他有效笔记。记录可区分观察、假设与已排除方案，并显式
说明归档、成员、段头、段正文、字符串编号、指令和存档坐标。输入变化后相关发现
标为待复核。笔记与账本仍是模型记录，不能替代独立字节核验。
恢复上下文版本为 16，按独立预算保留当前解析程序及代表样本 helper 的完整源码，
正常大小的程序可直接用于精确修改；超限源码保存完整本地文件并提供定位，
不把截断代码冒充可执行全文。姓名资源分别标明全局、目标脚本作用域和无记录的
分析 helper，展示下一实际验证步骤；原生消息 ID 的作用域不能混用。
已登记目标的空 helper 保持待修复，不能被其他章节的姓名或旁白记录掩盖；
恢复时保留该目标 helper 源码，要求先补齐其实际消息绑定再继续。存档测试的
当前失败也单独持久保存，直到同一目标实际重测成功，不因写入新程序或另一个

点击前情提要后按修改时间选最新进度存档，并计算 SHA-256。即使文件名、大小
和时间戳相同，只要内容变化就会重新分析；内容相同则先于存档解析和 AI 认证
返回本地结果，生成时间保持不变。恢复到曾总结过的存档也能复用对应记录。

每次新分析先核验当前台词在存档中的字节证据，再唯一定位脚本节点。`line` 必须
对应提取台词的 `position`；直接文本使用其字节偏移，索引型脚本使用有操作数证据
的位置，消息序号型脚本也可使用完整表遍历所核验的 ordinal。坐标均不代表已读顺序。
每个非空节点都必须有存档中的原生来源及位置证据，唯一台词也不能省略。
对已支持的 NXSC 固定头布局，还核对原生当前 caption 与所选完整计数记录一致；
历史记录、拼接字段或空节点降级均不能代替当前节点。当前 caption 仅按已知显示
控制符及空白规则比较，原始文本证据仍精确核验。无法唯一确定当前节点时明确失败，
不能按第一个、最后一个或最大位置猜测。
`facts.source` 必须采用已验证 `metadata["dialogue"]` 行的完整来源标识，原生字节
证据可使用同词干别名。匹配失败时返回来源、位置、锚点及其组合的匹配数量和
具体错误字段，不返回候选值或自动选择节点。`inspect_data(root="save")` 与正式
存档解析接收相同的已验证 `metadata["dialogue"]`，分析本身不算通过验证。
场景标签同样核对存档字节，随后保留在每一阶段请求中。

有存档实际保存、且经过字节核验的 backlog 时，按保存记录顺序提供历史，允许
跨脚本及代码位置倒退。没有 backlog 时，宿主从当前节点的同一来源中，按代码
位置选择当前节点及此前最近的最多 512 条记录，总 JSON 不超过 96,000 字节，
作为相关脚本候选。它们是真实脚本文本，不是已证明执行或阅读过的路线；宿主
不把整个编译模块的物理前缀当作已读剧情，也不混入其他来源或当前位置之后的代码。

缺少历史仍调用 AI，同时生成实质性的前情提要与当前进度。每轮分析都保留当前
存档场景、精确台词、已验证说话人，以及输入预算内最近最多 32 条原文。模型
优先依据这些近期内容重建人物处境；较远候选只有与近期事件、参与者或引用
相互印证时才用于补充，不能将整个窗口串成玩家已走过的路线。推断的前情简短
标注“根据脚本推断”，分支、身份和完成度证据不足时明确限制。`speaker=null`
时不得凭空归属主角或其他人物；仅有一句时分析该句体现的处境，不编造早前事件。

较长上下文按最多 48,000 字节分段，每段最多 24 条事件观察与 8 条不确定性，
按输入预算进一步限制笔记体积。候选脚本与真实历史使用不同字段和提示语，
分段及合并阶段都保留当前节点和上下文限制。最终请求保留近期原文及当前场景；
笔记过长时分层合并，保留事件、因果与人物状态。格式修复同时提供上一次回答，
避免重新生成时把已有的有效事实丢掉。
中间笔记优先要求字符串项；模型返回含非空字符串字段的对象时，将整个对象
规范化为 JSON 字符串，完整保留来源、位置及其他字段。空对象、没有有效字符串
的对象，以及 null、数字或数组项仍拒绝，规范化后继续校验数量、每项 2,000 字节
和总预算。最终 `recap/current_progress` 仍严格要求两个字符串，不能用对象替代。
作品简介、原始存档变量和上次存档事实也不进入提要请求，避免简介、全局标记
以及回退存档前的较远进度泄露后续剧情。模型须仅依据提供的前文，不补充作品知识。
脚本位置可能是引擎字节码偏移，不等同于阅读百分比；不根据全局解锁或已读标记
推断实际阅读历史。无法确认的分支、章节和完成度明确标为未知。

AI 返回格式固定为 JSON，并校验必填字段和长度：

```json
{
  "recap": "前情提要正文",
  "current_progress": "当前已确认的分支、章节或场景，以及无法确认的进度"
}
```

提要返回的格式、字段或长度不合规，或任一部分只是缺少历史、进度未知等占位
提示时，格式校正流程最多尝试 3 次。该检查能拒绝旧版停用式回复，不能替代
剧情事实审核。允许完整包裹 JSON 的代码围栏；不从说明文字中截取便利片段，
不补造缺失字段。认证、权限和计费错误（401、403、402）直接报告；可重试的
网络瞬断、超时、429 及指定 5xx 最多 3 次尝试并短暂退避，截断不盲目重放。

通过结构校验的分段笔记按模型、提示和输入内容缓存，重试可复用已完成分析；
无效 JSON 或只有占位提示的最终摘要不缓存，可另存至 `analysis-invalid` 供本地
排错但不再回传复用。最终摘要缓存包含提供方、用户
选择的模型及 `context.rs`、`report.rs` 指纹，切换模型或修改候选选择、提示
逻辑后不会继续命中旧摘要；相同配置和内容仍可离线复用。

新读取程序在独立的受限 Python 子进程内运行，有 AST 白名单、45 秒执行时限和
768 MiB 内存上限，只能处理宿主传入的字节与台词，不能访问文件、网络、进程
或 Token。安装包自带运行宿主，不要求玩家安装 Python。当前准备清单版本为 5、
模型契约为 4，提要缓存版本为 5，使旧的本地 `current_only` 展示和旧模型摘要
失效。准备清单和模型契约保持不变，存档验证版本单独为 3，脚本核验政策为 3；只有通过
当前版本检查的 Python 准备产物和摘要可以复用。公共 PSB／MDF 能力已同步打包，
解码通过不能替代完整准备验证。验证升级保留脚本研究和源码，旧产物不能直接
