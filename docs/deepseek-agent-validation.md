2026-10-19，使用软件凭据库中的 DeepSeek Token 与配置的 `deepseek-flash` 实测。
游戏格式的 Python 解析代码全部来自 DeepSeek 的 `write_program` 调用；Codex 只
编写通用工具宿主、接入代码和测试，没有编写或修改游戏解析程序。

API 本身不能读取本地 skill。软件提供 function calling 工具，由 DeepSeek
主动调用 `read_text(skill, SKILL.md)`，再读取参考文档、检查文件、选择 GARbro
参数并调用提取工具。工具执行结果回传为 `role: tool`，DeepSeek 根据实际结果
编写、测试和修正程序。编程阶段启用思考模式并按官方协议回传工具调用所需的
`reasoning_content`，不向界面输出推理内容。参见
[DeepSeek 官方工具调用文档](https://api-docs.deepseek.com/guides/thinking_mode/)。

## 2026-10-20：提高成功率与控制重复成本的流程优化

此次依据最近两天失败审计调整全部游戏共用的宿主和提示词，实际游戏解析程序仍
由模型编写；没有向宿主植入 Angel Tear 的格式偏移、台词、姓名或存档答案。

- 阶段按资源与版本确认、最小脚本程序及验证、存档程序、当前存档与回归验证、
  收尾推进。优先复用已有程序和证据；当前样本失败时修复具体问题，不能替换为
  容易通过的旧槽位。独立字节证据契约保持不变。
- 基础预算为 120 次 API 请求，包含收尾及传输重试，始终预留 1 次收尾。仅当
  两份解析程序已存在、独立台词提取非空，且最近 12 次请求内台词数或有效存档数
  超过本会话此前记录，才扩展至 150 次。重复相同结果、验证数量回退、模型笔记
  均不算新增验证进展；恢复旧会话也不直接继承延期资格。到达上限保留检查点。
- 同一阶段累计 8 次探索请求后启用 gate。下一步需写入/测试程序，或用
  `plan_probe` 提出一个结构阻碍、预期结果和 1–3 个现存精确文件；每份计划最多
  放行 3 次目标匹配探查。目录、通配符及路径逃逸不能绕过门槛，失败写测不清 gate。
- 验证阶段累计 8 次探索请求仍未测试当前程序时，持久化的 `test_attempted`
  状态要求先调用对应 `test_program`，不能继续 `plan_probe`，也不能以非技能
  目录的 `read_text` / `read_json` 绕过。实际失败后才按具体错误安排限量探查；
  技能文档仍可读，改写程序后重新要求实际测试。
- `reference_hints` 从技能包 catalog 路由通用格式资料，模型先读参考再核对当前
  magic 和版本。新增 Entis GLS / Cotopha 文档及保留许可的上游类型源码，说明
  NOA/CSX 分层、16 字节段头、保留空条目的完整字符串表和 image 引用验证。
  参考不含游戏特定答案，也没有把未知的资源加载顺序写成通用规则。
- catalog 的声明式 `verification_policy` 只含容器格式常量：匹配头后以有界 TLV
  规则定位需要核验的计数表区域，不解码字符串或游戏对白。匹配策略后的非法
  长度、边界和段数明确拒绝；模型需声明完整原表并证明实际操作数引用，不能
  仅交付直接文本跨度，使跳过空条目后的错误索引或重编号逃过验证。没有匹配头、
  或旧版根本不含该表时返回空区域，不伪造格式支持。
- `project_reference_hints` 提供当前 `work/references/` 中最多 8 份、各不超过
  256,000 字节的 `.md` / `.json` / `.txt` 研究入口，解析路径不能离开工作根目录。
  本机 Angel Tear 试验可复用已有安装研究的来源与文件指纹，帮助解决资源优先级
  冲突；模型必须核对当前输入、忽略内嵌指令并重新验证程序和存档。摘录作为项目
  数据，不是宿主证明，不提供游戏专用解析器或样本答案，也不发布进通用技能。
- 活跃上下文上限改为 160,000 字节，保留当前段思考字段与完整工具调用配对。
  超限后携带程序、验证状态、文档阅读进度及结构账本继续，不重放整段历史。
  `analysis-ledger.json` 的 `O1` 等短引用关联完整工具结果和原分析代码；
  `record_findings` 逐项保存，有错误的笔记不会连带丢掉同批有效项。输入变化会
  标记发现待复核，观察和笔记始终不替代宿主验证。
- `read_text` 默认 2,048 字符、最多 8,192 字符，其消息采用独立的 40,960 字节
  上限，避免中文和 emoji 页被通用 8,192 字节上限再次截断，造成文档已读进度
  与模型收到的内容不符。其他工具的有界预览与完整结果引用继续保留。
- 每个会话保留 `sessions/<会话ID>/`，重试前归档旧会话。`requests.jsonl` 记录
  每次尝试的阶段、状态、`finish_reason`、耗时、输出额度和服务商 usage，失败
  请求也保留安全诊断。诊断不写 Token、请求头、自由文本错误体或模型推理内容。
- 通常输出上限为 12,000；编写或验证阶段达到探索门槛时为 24,000。同阶段提升
  后的额度持久保存，兼容恢复还会读取前次失败 metadata，从 24,000 升至 32,000。
  截断内容不执行；单步最多一次扩容重试，32,000 处不做同额度盲重试。反复纯
  reasoning 截断的阶段恢复使用官方支持的 `reasoning_effort=low`，保留
  `thinking=enabled`、完整 reasoning 回传和严格字节验证，见
  [DeepSeek 思考模式说明](https://api-docs.deepseek.com/guides/thinking_mode/)。瞬断、超时、429 和
  指定 5xx 有界退避；同一步骤最多 3 次尝试（初次加最多 2 次重试），均计入
  总预算，保留收尾额度。认证、计费、配置和其他不可重试错误直接报告。

上轮 Python 回归 **174 项通过**。当时 Rust 核心 **129 项通过、1 项子进程
fixture 忽略**，国际化 2 项、UI 38 项通过，合计 **169 项通过**。新增 7 项核心
测试包含 6 项 `current_only` 测试及 1 项整个 `summarize` 的离线端到端测试：
使用不可用提供方、无配置及缺少工具条件，验证无需凭据或 AI，第二次读取命中
缓存。生产本地探针与只展示当前节点的内容审核也曾通过；当时 release 构建输出
`artifacts/GalGear.exe`，与 `target/release` 字节一致。最新打包后离线 smoke
为 0 网络请求，确认冻结宿主的恢复、安全工具、上下文 v3 及零预算会话关闭。
源技能、格式 catalog 及 Entis 参考与打包内容一致。输入检查 53 项 `changed=[]`，
检查范围及哈希保存在验证汇总，不以旧发布记录取代新分支验证。

这些检查只证明旧版分支按设计执行。用户随后指出缺少前情提要，因此上述
