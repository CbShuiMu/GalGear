# 我的游戏工具栏、嵌套收藏夹、批量操作与输出命名需求访谈

日期：2026-10-14。状态：需求澄清完成。第一轮用户接受除 Q3、Q12 外的推荐；Q12 改为不提供全局标签管理；第二轮用户明确 Q3 优先完整单行并允许提高最小窗口尺寸，Q13—Q18 全部按推荐。全部产品分支已逐项确认，不表示功能已实现。

本轮采用 grill-with-docs 的 grilling 与 domain-modeling 流程。旧基线中未被新要求取代的部分继续适用。

## 用户明确提出的要求

1. 移除“我的游戏”页面原先分散的游戏库及游戏数量显示，将这些数量与刷新、添加、标签筛选、搜索、排序等功能整理为同一排，放在“我的游戏”标题下方。工具栏采用区别于页面的背景与悬浮视觉效果。
2. 工具栏下方只保留整洁的游戏卡片；去掉封面左上角“已安装”“光盘镜像”等常驻类型角标。隐藏展示不等于删除条目数据。
3. 左侧 Tabs 添加“收藏夹”入口，使用已有 Google `folder_special` 图标，所有 Tabs 为纯图标，实际内容放在右侧。收藏夹页面通过用户创建的文件夹卡片浏览层级，初始为空，创建和添加游戏由专用工具栏完成。用户可以创建不同收藏夹，收藏夹可以包含子收藏夹，并将游戏卡片拖入收藏夹。
4. 后续统一交付 `artifacts/GalGear.exe`，不再按每次改动新增 `GalGear-next.exe`、`GalGear-icons-theme.exe`、`GalGear-reference-detail.exe` 等阶段程序名。安装版与便携版中的主程序同样使用 `GalGear.exe`；安装包及 ZIP 可以保留版本和发行类型标识。
5. 游戏页加入批量操作按钮。图 3 只作为参考，需提出区别于参考应用的交互与视觉方案；动作、选择范围、工具栏切换和边界反馈已逐项确认，见下表。再次明确移除游戏项海报左上角的“已安装”“光盘镜像”等类型文字，不再在列表中提示这类信息。

本次五点要求是新的明确输入；用户随后回复“除了 Q3 和 Q12 全部按推荐”，并要求每个游戏的标签只能在各自游戏详情修改。Q12 的具体限定优先于 Q10 原推荐中的批量标签动作：批量添加／移除标签取消。统一程序名是明确要求，不再重复询问；旧产物清理或归档不作为本次统一命名的必要条件。

收藏夹是游戏条目的逻辑归类容器，与磁盘上的游戏库文件夹不同。允许多归属，父级只展示直接成员及子收藏夹入口，删除只解除逻辑层级及归属；跨收藏夹拖放只新增归属，排除游戏后保留归属供恢复。

## 已核对的源码事实

- 当前标题行有刷新／取消扫描和添加菜单；搜索／类型／排序、全局标签管理、标签筛选、扫描进度及警告分散在其后，未形成独立吸顶工具栏。
- 标题及侧栏数字为全部目录条目数；底部库数为已配置的游戏库文件夹数量，包含当前不可访问的库。底部游戏数为经过搜索、安装类型和标签筛选后的匹配数。
- 条目总数包含手动添加和仍保留的失效条目。筛选覆盖整个目录，首次最多渲染 120 张卡片；不能将当前 DOM 数量当作游戏总数或全选范围。
- 当前窗口最小为 680×540；窄窗侧栏为 88px，主体可用宽约 560px。现有 CSS 在较窄窗口将工具栏换行，始终单排需要调整响应式收纳，不能仅增加背景和阴影。
- 卡片封面常驻角标显示已安装、镜像或不可用；当前没有独立红色失效警告。隐藏正常类型角标后仍需决定如何遵守原基线的失效提示要求。
- 旧失效条目保留有条件：所属扫描库仍配置，或属于手动条目。现有移除条目通过排除 ID 保持后续扫描不重新出现，并不删除磁盘文件；批量操作可延用该语义。
- 收藏夹模型、父子层级与成员关系均不存在；`Game.library` 是磁盘扫描根目录。`App.selected` 只表示正在查看的单个详情，不是多选集合。卡片及桥接层没有拖放事件。
- Tauri 的 `dragDropEnabled: false` 属于原生文件拖放设置，不等同于应用内部 HTML 拖放无法实现。
- `folder_special` SVG 已提供并注册，可复用。
- 列表全局标签管理提供统一改名和删除；详情标签编辑仅影响当前游戏。移除列表入口需要确定全局入口去向。
- 补充核对：网站标签的删除／改名抑制规则本来就按游戏保存；详情修改不会影响其他游戏。全局管理只是批量修改既有游戏规则。现有“重置标签规则”仅在全局管理入口，取消入口后需决定是否在详情提供单游戏恢复。
- 排除条目保留编辑、封面和资料记录；重新定位保留条目身份。扫描条目和手动添加条目的身份生成方式不同，恢复原条目不能简单模拟重新添加；当前仍需补齐专门的排除恢复入口。
- `scripts/build.ps1` 已复制构建结果到 `artifacts/GalGear.exe`，没有文件占用处理。当前目录中的多个阶段 EXE 来自另行交付；本轮只核对，不关闭正在运行的程序或清理产物。
- Cargo 内部构建文件仍为 `target/release/galgear.exe`；`productName` 已为 `GalGear`。未发现独立 ZIP／便携包打包脚本，交付名称要求不能写成所有打包流程已经验证。

核对文件：`crates/core/src/lib.rs`、`crates/core/src/scanner.rs`、`crates/ui/src/lib.rs`、`crates/ui/src/features.rs`、`crates/ui/src/icons.rs`、`web/bridge.js`、`scripts/build.ps1`。

| --- | --- | --- |
| Q1 | 统计口径 | 工具栏显示“X 个库 · Y 款游戏”；库数为已配置库数，游戏数仅统计 EXE 游戏及保留的失效 EXE 条目；筛选时显示匹配数／总数。移除标题、侧栏及底部的重复计数。 |
| Q2 | 悬浮行为 | 不同背景、细边框和阴影，并在滚动时吸顶。 |

| Q4 | 路径失效提示 | 正常类型角标全部移除；失效条目在游戏名称旁显示红色感叹号，悬停或聚焦提示原因，详情保留完整说明。取代旧基线在列表常驻失效文字的要求。 |

| --- | --- | --- |
| Q3 | 完整工具栏与窗口约束 | 优先保留完整单行工具栏，允许提高最小宽度／高度；原先将搜索收为图标、筛选收进次要菜单的推荐不采用。 |
| Q13 | 跨收藏夹拖放 | 将 A 中游戏拖到 B 只添加 B 归属，仍保留 A；要移出 A 使用独立“移出当前收藏夹”动作。拖动已选游戏时可一次加入所选全部游戏。 |
| Q14 | 批量视觉与进入退出 | 原工具栏切换为选择状态，显示已选数、全选、清空、加入收藏夹、移除及完成；保留必要的页面上下文，卡片显示勾选及选中边框。避免新增常驻工具条。收藏夹内区分“移出当前收藏夹”和“从游戏列表移除”。 |

## 定稿与验收场景

两轮问题已全部得到明确答复，需求澄清结束。正常模式和批量模式共用一排吸顶工具栏；Q3 的“完整”分别适用于各模式应显示的控件，不要求两套操作同时挤在一排。功能按钮仍可打开本身的菜单、选择器或确认框；这不属于因窗口过小而隐藏功能。

1. 正常模式在标题下方显示库数、游戏数、刷新／取消扫描、添加、弹窗标签筛选、搜索、排序及批量操作入口；没有重复统计、全局标签管理或封面类型角标。
2. 在允许的最小窗口尺寸、亮暗主题、已支持语言及字号下，正常和批量工具栏各自完整单行，无裁字、换行或横向溢出。最小宽度以侧栏、留白和完整工具栏实际占用测量，最小高度保障工具栏及卡片区域可用，长列表正常纵向滚动。
3. 扫描期间工具栏仍可操作；刷新按钮显示进度并提供取消，警告由工具栏入口展开，不在卡片区域放常驻扫描面板。
4. 封面不显示“已安装”“光盘镜像”“不可用”等角标；失效条目在游戏名称旁有红色感叹号，悬停和键盘聚焦可读原因，详情有完整说明。
5. 可创建多份及嵌套收藏夹；同级名称唯一，不同层级可同名；支持改名、移动，拒绝移入自身或后代；深层级可浏览且不遮挡操作。
6. 将同一游戏加入 A 和 B 后，两处各显示一次；从 A 拖到 B 不解除 A；重复加入提示已存在。父收藏夹只显示直接游戏和子收藏夹入口。
7. 单卡拖放、所选多卡拖放及卡片菜单加入都能完成归属操作；拖入文件夹卡片可保存归属，空文件夹可直接从工具栏添加游戏。
8. 收藏夹内“移出当前收藏夹”只解除当前归属；“从游戏列表移除”排除条目，后续扫描不重新显示。不删除游戏文件、存档或补丁备份。
9. 删除父收藏夹前展示涉及的子收藏夹与游戏数量；确认后删除其逻辑层级及归属，其他收藏夹及“我的游戏”中的条目保留。
10. 收藏夹、归属在刷新和重启后保留；重新定位保留游戏身份及归属；恢复被排除的原条目时恢复现存收藏夹归属，已删除收藏夹不重建。
11. 匹配 300 款、首批只渲染 120 张时，全选仍选择 300 款；改变页面／收藏夹／搜索／筛选清空选择，排序保留选择，完成退出后清空。成功项退出选择，失败项保留选择并可查看原因及重试。
12. 标签只能在当前游戏详情修改；修改、删除及恢复网站标签均不影响其他游戏；恢复前确认，重新导入缓存网站标签并保留其他手动标签。已有逐游戏规则保留。
13. 本轮交付主程序固定为 `artifacts/GalGear.exe`，不再产生按阶段命名的新 EXE；安装／便携交付的主程序同名。旧产物清理不是验收前提。
