# 源码模块边界

存档发现支持专用目录与明确的文件集合，普通查找、AI 直接应用、手动指定及快照恢复共用 core 中的范围模型。协议与兼容规则见 [存档发现与文件集合](save-discovery.md)。

`crates/core` 负责可脱离界面使用的业务逻辑；`crates/i18n` 和 `crates/tags` 提供两端共用的国际化与标签规则。UI 不依赖桌面运行时，桌面命令调用 core，再通过既有 JSON 协议与 UI 交互。

## Rust/WASM UI

- `lib.rs` 声明模块并导出 WASM 入口；`bridge.rs` 是 JavaScript 传输与 DOM 边界。
- `models.rs` 放序列化模型；`state.rs` 组合各功能状态，不堆放各功能的临时字段。
- `events.rs` 接收浏览器事件，`actions.rs` 处理导航与跨功能协调，账号、下载、补丁各自处理所属动作。
- `requests.rs` 独占请求编号与待完成请求。界面是否阻塞直接从队列计算；新增请求种类时在 `Pending::blocks_ui` 中声明策略。
- `responses.rs` 处理后端响应；`view.rs` 绘制应用外壳，`widgets.rs` 提供无状态的 HTML 基础函数。
- `library/` 分开维护状态、查询、动作、页面和弹窗。筛选与层级查询只接收需要的目录、配置或功能状态，不依赖整个 `App`。

生产模块显式导入依赖，不从父模块通配导入。可独立计算的辅助函数应接收具体数据；接收整个 `App` 的函数用于交互编排或页面组合。

详情页顶部品牌与制作资料共用已应用手动覆盖的 `Game.metadata.brand`。旧配置中的 `summary_brand` 仅为兼容保留，不再用于显示或在关联资料时生成，避免切换资料源后仍显示旧品牌。故事阅读模式保留行宽限制，编辑模式的输入区随资料卡片宽度伸缩。

详情编辑模式隐藏标签换源入口，在取消按钮左侧提供“重新匹配”。`ui::game_setup` 复用导入确认表格，但只维护当前游戏的重新匹配草稿，不混入后台扫描的新游戏；取消保留详情编辑草稿，失败保留弹窗，保存成功后退出编辑。`rematch_game_metadata` 与导入共用刮削和持久化流程，`core::game_setup::prepare_rematch` 复用资料覆盖规则，更新标题、资料、标签及其来源并清除旧手动覆盖，保留启动、存档和游玩配置。封面沿用数据源首图与内容寻址缓存，无图或下载失败保留原图。

标签筛选同时匹配本地 `Game.tags` 和当前资料中的品牌、开发商、发行商及制作人员。候选搜索、选取和游戏匹配共用 `library::filter_tags`，名称拆分与详情页共用 `galgear_tags::credit_names`，按规范化后的完整名称匹配，多选取交集。制作资料参与筛选时不回写本地标签，资料源和标签源继续独立保存，删除或改名的普通标签仍遵循本地编辑规则。当前制作资料中的名称只要仍然显示，就可参与筛选，更新资料后筛选随之更新。

标签筛选中的「制作组」搜索在聚焦时以浮层列出游戏库当前资料里的品牌，输入后按名称缩小范围，失焦后收起。候选列表不占弹窗正文空间，并根据可用窗口高度向上或向下展开。通过该入口选中的名称只匹配品牌字段，并与其他已选筛选条件取交集。

详情页本地标签的整个主体（文字及留白）共用短按筛选、长按排序的命中入口，两侧编辑和删除按钮保持独立操作。标签与卡片通过 `web/press-gesture.js` 共用 380ms 长按阈值和 6px 移动容差；后台重绘不重置长按计时，超过容差后释放不会误触筛选。也可聚焦后用 Alt＋左右方向键移动。`web/detail-tag-reorder.js` 负责空白占位、跨行让位与拾起/落位动画。跟随位置在独立合成层直接更新，拾起动画只播放一次；指针事件按帧合并，落点几何只在布局变化时重新测量，静止时不运行拖拽循环，边缘滚动按时间推进。拖动期间隐藏编辑和删除操作，Escape、失焦或移出标签区域释放会取消。`ui::detail_tags` 根据游戏 ID、标签名和插入目标校验移动，通过既有 `edit_tags` 保存顺序；成功后 `Game.tags` 与编辑模式的 `draft-tags` 保持一致，失败保留原顺序。拖动及保存期间延后 DOM 更新，结束后应用最新 Rust 视图，避免背景响应打断动画。尊重系统减少动态效果偏好；手势回归运行 `node --test scripts/test-detail-tag-reorder.cjs scripts/test-library-card.cjs scripts/test-library-reorder.cjs`。

刮削标签统一由 `core::providers::Metadata::tag_names` 提取，只规范化数据源的 `tags` 字段；各数据源解析器不再把制作人员和组织名称混入该字段。首次关联与缓存补全沿用这一入口，人员和品牌仍由资料字段提供筛选。旧版已经保存的本地标签不按人员名称自动删除，以免误删手动标签或与人员同名的真实分类；重新选择标签数据源时，沿用显式覆盖标签列表的行为，保存新的纯标签列表，保持游戏资料来源不变。

## Tauri 桌面端

`main.rs` 只调用 `desktop::run`；`desktop.rs` 负责启动、协议、托盘与命令注册。扫描、资料、封面、账号、下载、存档、补丁及启动工具分别由对应模块实现。

`state.rs` 负责共享配置、游戏目录的持久化和跨功能写入互斥。扫描、账号刷新、下载、补丁预览、存档恢复和运行进程的内部状态由各自模块封装；跨模块通过操作接口读取下载结果、使下载计划失效等，不能直接操作对方的锁或临时计划。

存档、补丁与启动流程仍共用 `state::begin_write`，避免功能拆分后失去互斥。新增 Tauri 命令应放在所属业务模块，并在 `desktop.rs` 注册，保持现有命令名和序列化字段兼容。

游戏、存档和补丁目录统一通过 `folders` 打开；各命令保留所属业务的路径校验。Windows 端将目录解析为 Shell 项目再打开，避免 `explorer.exe` 命令行解析路径后跳转到默认目录。

`core::downloads` 封装文件流接收、进度、取消、体积检查及不覆盖已有文件的落盘；`fan_account` 和 `data_sources::moyu` 分别负责各自的授权与文件获取规则。桌面 `downloads` 共用任务互斥和进度事件，UI 的 NextMoe 下载请求不触发无关的 2DFan 账号刷新。NextMoe 的下载 ID 与展示用网页 URL 分开传输，签名下载 URL 不进入持久化配置或前端。

`core::fan_http` 为 2DFan 资料查询与账号会话提供共用的 Token/Cookie、超时、响应大小及同源重定向规则。桌面数据源入口从既有 `GalGear/2DFan/…` 凭据条目读取会话，`data_sources::Credentials.fan` 只在内存中传递且不参与序列化；搜索、资料、标签、封面候选和补丁列表使用该会话，没有凭据时匿名访问。CDN 图片和文件下载不携带站点凭据。

## OAuth HTTPS 回调

`core::data_sources::oauth` 负责内置应用授权、PKCE、本机监听和令牌轮换；桌面命令负责打开系统浏览器、取消与结果保存。`cloudflare/oauth-callback` 是独立部署的无状态 Worker，绑定 `galgear.cbshuimu.net`：NextMoe 仅中继授权码，Bangumi 则保管发布版 App Secret，签发短期会话及加密换码票据，并调用上游换码/刷新。用户令牌只在桌面凭据库持久化，不保存在 Worker。协议与旧令牌兼容见 [OAuth 回调服务](oauth-callback.md)，取舍见 [ADR 0002](adr/0002-builtin-oauth-applications.md)。

## 运行诊断

桌面 `diagnostics` 在主程序启动时创建安装目录下 `logs/galgear_启动时间.log`，记录启动与退出、命令关联、后台错误、前端异常和崩溃。Windows 端在原生侧订阅 WebView2 进程故障，前端在应用页面或弹窗切换后报告 DOM 与帧回调进度。日志边界负责脱敏，core 不依赖桌面日志实现。覆盖范围、故障排查和隔离验证见 [运行日志](runtime-logs.md)。

## 游戏截图

`core::screenshots` 维护快捷键校验、游戏内 `screenshots` 路径边界、PNG 原子写入和最近截图读取；桌面端 `screenshots` 的独立线程管理前台游戏识别、Win32 热键、客户区采集和剪贴板；后台键盘接收及管理员输入转发由 `game_input` 统一管理。UI 通过 `configure_tools` 统一保存卡片中的工具、保留份数和截图快捷键，通过 `latest_screenshot`、`open_screenshot_folder` 读取预览和打开目录；`screenshot-updated` 只携带游戏 ID，预览响应用游戏 ID 和请求代数隔离迟到结果。

设置位于“路径与备份 → 存档备份与内置工具”，新配置默认启用 `Shift+S`，快捷键与保留份数并排，通过卡片右上角保存。只在库中游戏位于前台时注册，离开游戏后释放；快捷键冲突或设置写入失败保留旧配置。游戏识别使用前台进程的真实可执行路径，支持游戏目录内的子启动器。GalGear 退出后快捷键失效。

截图以 UTC 时间命名，PNG 保留客户区实际物理像素，不做缩放或有损压缩；详情卡片的显示预览可以缩小。保存成功后才通知刷新，剪贴板同时提供原始 PNG 和 bottom-up 24 位 CF_DIB（包含 DWORD 行对齐，Windows 可合成 CF_BITMAP / CF_DIBV5），复制失败独立提示并保留已保存图片。截图目录拒绝符号链接和重解析点，读取预览不创建目录；“打开目录”会按需创建。

当前采集为前台客户区的屏幕像素复制，排除标准标题栏和边框；游戏需完整位于屏幕内。Magpie 通过公开的 `Magpie.SrcHWND` 属性（旧版回退到 owner）与游戏关联；全屏截取整个缩放输出客户区，窗口模式优先截取 `Magpie_Renderer` 子窗口。保留缩放后的实际物理像素，不对原游戏截图二次插值。采集前后均校验前台及输出关联。参见 [Magpie ScalingWindow](https://github.com/Blinue/Magpie/blob/v0.13.0/src/Magpie.Core/ScalingWindow.cpp) 和 [Windows 剪贴板格式](https://learn.microsoft.com/en-us/windows/win32/dataxchg/clipboard-formats)。独占全屏、受保护画面、自绘标题栏和第三方覆盖层可能影响结果，建议窗口或无边框模式。不会回退为整张桌面截图。工作线程的短提示显示在游戏客户区右下角（Magpie 启用时跟随缩放输出客户区），保留内边距，小窗口内收窄提示；目标隐藏或关闭时不回退到屏幕角落。提示不抢游戏焦点，使用应用明暗/配色与输出窗口的 DPI。热键同时接收 WM_HOTKEY 与后台 Raw Input，补充仅依赖系统热键消息的触发方式；只在已识别的前台游戏中注册原始键盘接收，失焦恢复原注册，不记录按键内容，长按及两种通知去重。

原生隔离验证：`cargo test -p galgear --locked native_client_pixels_clipboard_and_hotkey_conflict -- --ignored --test-threads=1`（需要交互式桌面，会创建测试窗口并将测试图像写入剪贴板）。设置 `GALGEAR_TEST_MAGPIE=1` 时，测试等待手动对测试窗口启动 Magpie 全屏缩放，并校验截图尺寸等于显示器物理分辨率及中心像素。提示定位隔离验证：`cargo test -p galgear --locked native_notice_stays_inside_game_client_without_activation -- --ignored --test-threads=1`，创建不同位置和大小的原生测试窗口，检查客户区内右下角定位、不抢焦点及隐藏目标处理，不写剪贴板。普通测试不启动真实游戏、不操作真实存档。

管理员游戏可能让普通权限进程收不到键盘消息。`game_input::elevated` 在识别到这种前台窗口后，以系统授权启动同一可执行文件的 `--galgear-game-input` 辅助模式；每次 GalGear 会话只启动一次，取消后可保存快捷键重试。辅助进程验证父进程可执行文件和窗口归属，只接收截图与字体面板两组快捷键并回传对应槽位、目标 HWND 与配置代数，不接收文件路径、不执行截图或写入。主进程再次核对前台游戏后完成原尺寸 PNG、剪贴板和主题提示。失焦或修改设置撤销旧代数，退出销毁消息窗口，辅助进程随之结束；UAC 等待不阻塞设置和消息处理。键盘接收仍遵循 [Windows Raw Input](https://learn.microsoft.com/en-us/windows/win32/inputdev/using-raw-input)，不记录按键文本，也不向游戏注入代码。

## 更新检查与 Skill 手动安装

`core::ai::skills::status` 只读本地安装与 commit；`latest_commit` 只查询远端 main 的 SHA，与 `sync` 共用查询及校验逻辑，不写目录、不下载资源包；`sync` 负责固定仓库 main 的检查、按 commit 下载和原子替换，并返回是否更新。桌面 `skill_package` 不再有启动任务或 OnceCell；只有 `check_skill_update` 命令能同步，`get_ai_runtime` 仅查询本地状态，`check_skill_version` 在后台线程只读查询远端版本，无需独占资源租约。AI 任务持有资源读取租约，更新持有排他租约，防止替换仍被使用的目录。

UI `skill_update` 在设置 → 更新中复用 GalGear 卡片布局，显示 Skill、本地 commit、固定仓库和“更新”按钮。每次启动完成初始化后，UI 并发后台检查 GalGear 和 Skill 版本，不阻塞本地功能、不自动安装。GalGear 检测到新 Release 时自动弹窗显示版本，右下角依次为“稍后处理”“立即更新”；稍后处理仅关闭本次提示，下次启动仍会检查，立即更新复用既有下载校验、替换与重启流程。无可用安装包时保留提示并禁用立即更新。没有新版本或后台检查失败时不弹窗，失败信息显示在更新卡片中；Skill 继续只显示卡片通知。检测到新版本时，在版本标记左侧显示同样式的“待更新”，设置左侧“更新”入口显示圆形数量提示，GalGear 和 Skill 各计一项，最多为 2。关闭 GalGear 更新弹窗保留通知，Skill 安装成功后清除对应通知；迟到的后台检查不能恢复旧通知。更新不阻塞本地游戏库，重复点击合并为一次请求；成功后刷新版本和 AI 可用状态，迟到的启动查询不能覆盖更新结果。失败保留本地版本，可重试。

## 快捷键录制

`ui::shortcut_picker` 管理按键录制、重置、取消和确认后的设置草稿；DOM 桥接仅转发物理键代码及修饰键并维护弹窗焦点。三项快捷键通过 `configure_tools` 统一校验并保存，由 `runtime::canonical_hotkey` 规范化后检查重复组合；Magpie 配置仍沿用其位掩码适配入口。字体面板工作线程跟随已保存的 `font_hotkey` 更新系统热键与 Raw Input，旧配置默认 Shift+T。

## 游戏字体面板

`game_window` 和 `game_input` 统一游戏窗口识别与后台快捷键。Rust 原生 `font_tools` 面板负责游戏内调节和本地文字预览，core 维护参数及版本化 IPC。C++ 使用 SimpleFontHook 兼容构建，运行时兼容代码集中在 `native/font-hook/compat`，负责转区字体准备、运行中安装及引擎刷新。上游原 UI 隐藏，更新自动重建兼容组件。协议、更新与实时刷新限制见 [游戏内字体面板](font-tools.md)。

## 别名检索与数据源偏好

详情编辑保存成功且标题实际改变后，UI 发起非阻塞的 `refresh_title_metadata`，使用新标题分别搜索该游戏当前的资料源和标签源。只有唯一结果且词条身份不同才刮削，零个、多个或同一词条均保留现状；同源搜索和同一 URL 的刮削在一次更新内复用。`core::game_details::title_refresh` 维护来源、词条身份与覆盖规则，桌面 `metadata::title_refresh` 负责网络与持久化。网络等待不持有配置或目录锁，提交前重新检查标题、来源及各目标内容，丢弃过时结果；某一来源失败不阻止另一来源成功更新，并显示失败提示，已保存标题不回滚。

`GameEdit.tag_source_url` 记录独立标签词条，首次游戏关联和手动更换标签源时保存；更换资料源前保留原标签关联。旧配置默认 `None`：从未分离的标签沿用资料关联，旧版独立标签因未保存来源只能回退到标签入口偏好（再回退全局默认），重新关联后即可准确保留逐游戏来源。自动更新覆盖对应的手动标签规则或资料字段保护及发行日期摘要，保留用户输入的新标题、启动配置和存档设置。封面使用新资料词条的封面列表首项；仅标签源匹配新词条时使用该标签词条的首项。通过既有数据源封面列表与下载校验获取图片，与手动选图共用内容寻址缓存，不覆盖游戏目录中的原图；与资料一起提交封面覆盖路径。无封面或下载失败保留原图，失败独立提示；提交前检查标题、词条和封面是否被后续操作修改，过期下载不改变当前封面。

首次确认不同的唯一词条后、开始刮削前，桌面端发出 `title-refresh-started` 事件，载荷为请求携带的 `requestId`。UI 仅接受仍有效的对应请求，在右下角通知区独立显示“正在同步封面，标签与资料”，不设置自动超时，也不被普通通知替换。请求完成（包括封面下载与持久化、失败或结果过期）时移除对应提示；并行同步共用一条提示，直到最后一项有效同步结束。迟到的开始事件不得恢复已关闭提示。

扫描结束（包括每次启动的增量扫描）后，后台为 `Game.aliases` 为空的游戏查询 NextMoe 多语言名称和别名。已有 NextMoe 关联按作品 ID 查询，其余只接受名称完全匹配的唯一游戏，避免混入续作。别名写入既有原子目录缓存，后续扫描及资料编辑保留；旧缓存默认空列表。失败或未匹配项保留为空，下次启动重试，同一运行期间不重复请求。游戏库文本搜索仅匹配标题和别名；标签通过独立的标签筛选匹配，不参与文本搜索。别名查询不改变资料来源。

`Settings.source_preferences` 保存资料、标签、封面、补丁入口的手动来源选择；没有覆盖时跟随 `metadata_provider`。旧配置默认空映射，已有逐游戏资料关联仍保留。补丁仅支持鲲Gal/2DFan，默认来源不支持补丁时显示全部。鲲Gal仅为显示名称，API 标识与凭据仍使用 `nextmoe`。

## 汉化启动器与游戏运行会话

`core::runtime::Monitor` 属于应用实例，由桌面 `tools::RuntimeState` 持有并显式共享给计时、启动检查、存档备份/恢复、补丁写入和封面处理。启动后立即从 `Child` 句柄记录 PID 与创建时间，启动器即使瞬间退出也不会丢失交接线索。`runtime/processes.rs` 采集一次进程表和窗口表；`runtime/monitor.rs` 在锁外完成系统采集，锁内仅更新会话，较旧的并发快照不能覆盖新状态。桌面观察周期为 1 秒，耗时采集运行在后台任务中。

识别后继进程综合父子关系、创建时间、可见窗口、前台窗口及启动目录，不要求与配置的 EXE 同名或使用 `.exe` 后缀。对于中间启动器过快退出而未被采集的情况，可接续启动之后在同目录创建的窗口进程；不接纳启动前已存在的工具。进程身份同时核对创建时间和退出时间，避免 PID 重用以及保留句柄的已退出对象被当成运行进程。每轮独立查询一次前台窗口，兼容带 owner 的游戏对话框。

`runtime/monitor/confidence.rs` 以时间常数 2 秒的 EMA 积累证据，可见窗口、前台窗口和启动关系分别贡献 0.35、0.40、0.25；仅靠同目录识别时使用一半关系权重。配置的游戏映像本身按强关联处理，覆盖 Steam 等中间层未保留父子关系的情况。目标仍存活时持续验证候选：分数至少 0.6、领先当前目标至少 0.3、领先其他候选至少 0.25，且优势连续保持 5 秒才换绑，每次会话最多执行 3 次此类换绑。候选的创建时间和首次观察时间不得早于目标，已经替换掉的进程不再被选回。游戏最小化或切换焦点不会直接停止计时，换绑本身保持同一个游戏的计时检查点和自动备份会话。

目标退出后的唯一关联窗口可立即接续；无父子关联的目录候选和多个窗口并存时，需要至少 3 秒的观察、0.6 的分数和 0.25 的领先差距。没有明确领先者时保留 `Unknown`。启动器退出后仅剩一个有映像路径的关联进程，连续观察 10 秒后可确认，覆盖无窗口加载过程。超过 3 秒的采样中断会清除置信度和待确认的连续优势，休眠或采集失败期间不补算证据。

目标退出后保留 3 秒交接观察期；检查失败、权限不足或尚未确认交接时返回 `Unknown`，不累计不确定时间，也不触发结束自动备份。确认没有后继进程才返回 `Stopped`。会话证据只保存在内存中；应用重新启动后仍能按原有的精确路径/同目录同名 PE 识别运行进程，但无法还原已退出启动器的历史父子链。手工从外部启动、且配置 EXE 早已退出的异名临时进程仍可能无法识别。

设计参考：[LunaBox：如何较为正确地判断一个 galgame 真正的进程](https://www.kungal.com/topic/4648)。本实现保留 GalGear 的 `Running / Stopped / Unknown` 协议，未引入额外依赖。Windows 隔离进程测试会让测试启动器先退出，再观察更名为 `.tmp`、带窗口的实际子进程；规则测试覆盖 PID 重用、驻留启动器、最小化、后继交接和计时/会话结束。


## 离线游戏库与全局存档备份

游戏目录失效时只更新 `Game.available`，保留条目、资料、收藏和游玩记录。UI 在库卡片和首页卡片右上角显示红色圆形感叹号，允许进入详情编辑资料，禁用启动与游戏配置。提交启动配置时桌面端重新检查路径，覆盖编辑过程中磁盘离线的情况。

桌面 `library_devices` 每两秒在后台读取 Windows 逻辑磁盘位图与已配置游戏库的可访问状态，变化时发出 `library-devices-changed`。UI 复用非阻塞 `BackgroundScan`，连续变化在当前扫描结束后合并补扫，完成时静默更新。全量刷新和增量扫描共用 `catalog::identity` 匹配已有安装记录，优先匹配规范化后的启动路径，同目录仅有一个已有条目时允许目录匹配，保留原 ID 和启动项。全量刷新仍重新读取文件与封面。同目录多个手动版本只有明确匹配时才复用身份。

启动加载完独立游玩记录后，`library::repair_scan_duplicates` 清理旧版目录哈希产生的空白扫描副本。仅当同目录存在唯一手动条目，副本仍为默认待确认状态，且没有资料、用户配置、收藏、游玩记录或备份数据时才清理。自定义封面通过 `cover_overrides` 保护，按内容共享的封面增强缓存可以供其他条目复用。备份检查覆盖当前、旧根目录及游戏内目录，包括未完成写入；配置过的备份盘离线或读取失败时保留条目。清理通过原子目录缓存写入完成，保留原条目身份、旧配置和备份索引；有数据或身份歧义的条目继续保留。

条目删除统一永久清除资料、配置、收藏归属和游玩记录，以 `excluded_paths` 保存最小扫描排除路径。显式添加游戏或移除后重新添加库目录可重新导入，旧版排除档案仍可通过原入口查看与恢复。磁盘游戏、存档与备份由独立操作管理。

`core::snapshots::storage` 负责全局目录中的 `games.json` 身份索引与时间命名。`backup_folder` 为空时使用应用数据目录的 `save-backups`，`backup_legacy_folders` 记录待迁移来源，旧配置默认空。核心迁移先校验并发布完整副本，重试复用已发布内容，然后清理源目录；改名同时更新 manifest 和恢复日志。目录和索引路径拒绝符号链接及 Windows 重解析点。桌面备份、恢复和目录设置共用 `state::begin_write`，沿用现有运行状态检查、恢复预览和回滚。


## 批量资料确认、首次启动与自定排序

“添加 → 添加游戏库”使用 Windows 原生目录多选。选择结果通过 `choose_library_folders` 返回数组，`add_library_folders` 在单个后台任务中规范化路径、收集无效目录并原子保存一次配置。规范化后的重复目录跳过，父子目录作为独立库保留，扫描沿用已有路径去重。已有库的排除记录保持原语义，重新加入已移除的库时恢复可扫描状态。全部重复、全部失败或取消选择时无需扫描。

有效目录保存成功后统一增量扫描，若已有扫描正在运行则合并为结束后的一次补扫。扫描沿用进度与取消入口。添加结果显示新增、重复及失败数量，失败目录按每页 40 项展示，关闭报告后再进入资料确认。配置保存失败时整批有效目录均未提交，可直接重试。原有单目录命令继续服务手动路径入口。

批量注册以集合去重，恢复排除记录时沿各路径的祖先查询整批新增根目录，处理量随路径总长度增长。旧版排除条目只遍历一次，避免目录与排除记录双重循环。性能验证使用隔离数据，可运行 `cargo test -p galgear-core --release --locked --lib batch_library_registration_scaling -- --ignored --nocapture`（最多 5 万库、5 万旧排除条目和重复选择）及 `cargo test -p galgear --release --locked batch_library_disk_stress -- --ignored --nocapture`（2 千真实目录、1.1 万次选择及单次空库扫描）。前端 `scripts/test-library-setup.mjs` 覆盖 1 万目录只提交一次、只扫描一次，以及 1 万失败项的分页。原生多选与取消使用 `native_multiple_folder_picker_and_cancel` 交互测试。

资料确认表格中的游戏路径支持鼠标悬停或键盘聚焦时显示下划线，点击后通过 `open_game_folder` 直接打开系统文件管理器，无需二次确认。路径按游戏 ID 从目录记录中读取，沿用桌面端的目录存在性校验。

资料确认允许留空启动程序，新配置以 `GameEdit.launcher_pending` 记录待选状态，旧配置默认 false。UI 在首次启动时调用 `list_game_executables`，只有一个候选时直接选用，有多个候选时显示游戏目录直属普通 EXE 的名称及缓存图标供用户选择。两种情况均通过 `confirm_game_executable` 写入启动路径和工作目录。该命令重新枚举并校验候选，沿用 `state::begin_write`，返回新启动路径的运行状态以继续启动流程。已手动配置的启动程序继续沿用。

`core::library_order` 维护 `Settings.custom_order`。首次选择自定排序时按品牌和规范化游戏名初始化，名称忽略大小写、空格及标点，使同品牌且同名前缀的作品相邻。移动按既有顺序处理整组条目，保留筛选隐藏项的相对顺序，新增条目追加，旧配置默认空列表。DOM 长按、叠放预览、让位动画及边缘滚动位于 `web/library-reorder.js`，Rust 验证移动并保存。键盘可用 Alt 加左右方向键调整位置。

扫描在后台执行，`scan-progress` 只传递目录计数，约 120ms 节流，完成后一次合并完整目录。进度以各游戏库直属子目录为单位，跳过的资源目录不计入总数。资料确认每页渲染 40 行，自动查询与资料保存共用三个并发请求额度，避免数百行同时构建 DOM 或发起网络请求。资料保存的配置和目录写入放在后台线程，失败条目保留草稿以便重试。

导入阶段由 `core::catalog::title` 统一判断目录名：扫描游戏库和手动添加 EXE 时，遇到 `game`、`data`、`bin` 等通用名就沿父目录寻找最近的有效名称，也允许向上越过用户所选的游戏库根目录。名称原样保存为游戏标题并填入资料确认窗口，保留编号、空格及标点；安装目录和启动程序路径保持原值。增量扫描复用缓存时也修正无资料且无手动标题的旧通用名。

自动刮削与手动搜索统一调用 `search_metadata`，只提交搜索框当前名称和所选数据源，不重新读取目录或覆盖用户输入。空名称跳过请求并留待确认。返回一个有效候选时自动选中并确认；返回两个及以上候选时，按数据源返回顺序预选第一条，保留全部候选供用户切换，由用户手动确认。确认依据为返回条数，不要求查询词与候选标题或别名完全一致。空结果、失败和多条待确认行计入未匹配或失败数，点击保存前不写入资料或封面。候选继续使用 `Resource` 数组协议，`aliases` 缺失时默认空列表。

自动刮削通过 `metadata::search::Service` 复用 HTTP 连接池，整个查询（含排队和凭据准备）最长等待 45 秒。后台搜索最多三个，超时后阻塞线程仍持有名额直到实际结束，避免连续重试堆积线程。UI 按真实在途请求补充队列，超时、空结果和解析失败均推进进度；停止后的迟到响应按请求 ID 丢弃。再次自动刮削跳过已确认条目。右下角消息实时显示已处理数、总数与未匹配或失败数，完成或停止后显示汇总。批量保存响应只返回当前游戏及其配置，前端同时兼容旧版完整设置响应。

## 首次语言选择与批评空间

UI 的 startup 模块负责首次语言选择和后台任务启动顺序；语言与默认数据源通过既有 set_language 原子保存，旧配置不重新引导。批评空间只读查询位于 core 的 data_sources/erogamescape，卡片使用本地平台图标。接口、兼容性与验证限制见 [批评空间与首次语言选择](erogamescape.md)。

## 游戏库卡面尺寸

首张显示设置卡片中的“游戏库显示模式”以图示胶囊提供海报墙与封面加标题，持久化为 `Settings.library_display_mode`（`poster/caption`），新旧配置默认海报墙。`set_library_display_mode` 原子保存后才切换，迟到的设置读取不能覆盖已保存模式。封面加标题先复用海报墙的居中铺满适配，再从该画面上下各裁 4%，标题居中最多两行，卡片行间距为 12px。该模式不渲染悬停遮罩，悬停或键盘聚焦时封面保持清晰，键盘焦点轮廓与选中标记继续显示。游戏库与收藏夹共用卡片入口、框选、批量选择和拖拽；拖拽副本保留标题几何占位但隐藏文字，落位与保存结束后恢复。尺寸快捷键说明通过尺寸标题旁的问号在悬停或键盘聚焦时显示。

“设置 → 显示与交互”首张卡片依次提供小、中、大三档，持久化为 `Settings.library_card_size`（`tiny/small/normal`），旧配置默认大档。与历史 `card_size/cover_scale` 独立，不改变首页或详情封面。`set_library_card_size` 通过现有原子配置写入机制保存；UI 仅在成功后应用，并隔离保存前已在途的设置响应。

游戏库及收藏夹内可按 Alt＋滚轮、Alt＋↑/↓ 调节，向上放大，向下缩小。Alt＋滚轮覆盖页面所在的整个滚动区域，包括卡片缩小后留下的空白。输入框、弹窗和拖拽期间不响应。`library/size.rs` 统一设置入口与步进规则，`web/library-size.js` 负责 DOM 测量与输入转发。大档沿用 227–312px，中档和小档的目标宽度分别为 177–205px、145–166px；每缩小一档至少多一列，必要时均匀收窄。工具栏保持与完整列右边缘对齐，筛选后不足一行也保留空列。窗口最小宽度继续按大档四列计算，不随用户档位改变。

中档卡片的长标题最多四行，小档最多三行。大、中、小档卡片的标题字重依次为 600、400、300。空间不足时裁切标题，标签保留可滚动且可聚焦的区域，操作按钮随卡面收紧。拖拽预览和落点沿用实际卡片测量；尺寸切换不改变选择、排序及收藏归属。验证：`node --test scripts/test-library-size.mjs scripts/test-library-toolbar.cjs scripts/test-library-drag.cjs scripts/test-library-reorder.cjs`。

卡面标题、封面和标签内容共用短按进入详情的动作。`web/library-card.js` 为点击、框选和长按排序统一识别标签滚动条，标签滚动会取消待触发的长按，触摸标签时保留原生滚动。自定排序沿用 380ms 长按拾起卡片及拖动落位，拖拽后的释放点击由桥接层抑制；底部按钮继续派发各自的动作。回归验证包含 `scripts/test-library-card.cjs`。
