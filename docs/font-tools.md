# 游戏内字体面板

游戏库中的游戏在前台时，默认按 **Shift+T** 打开或隐藏 Rust 原生悬浮面板。Esc 和关闭按钮恢复游戏焦点；面板跟随游戏客户区、DPI 和 Magpie 输出窗口，明暗配色与 GalGear 一致。小于约 315×471 物理像素的客户区不显示面板；独占全屏不保证外部窗口可见。

设置 → 路径与备份 → 存档备份与内置工具中，可修改“字体调节面板快捷键”。点击快捷键框后按下组合键，右下角依次为“重置”“取消”“确认”；重置清空本次录制，取消放弃，确认只更新卡片草稿，点击卡片“保存”后生效。字体面板、截图和 Magpie 的快捷键不能重复，旧配置仍使用 Shift+T。

## 功能

- 选择已安装字体，名称留空保留游戏字体。
- 高度、宽度比例（50–300%）、字距（−20～60）、行距（−80～200）、字重（100～900）。
- 可选垂直度量：上行高度 100～2000‰，数值越大，上方预留空间越多；下行高度 −2000～−1‰，数值越负，下方预留空间越多。两项说明分别显示在对应输入框下方。
- 可选字符集伪装，显式选择源与目标：Default、Shift-JIS、韩文、GB2312、Big5。
- 上游运行时映射：关闭、日文旧字形、繁转简、简转繁；可选源编码检测失败时的回退代码页。
- 中英日文字及数字随输入即时预览。预览只模拟本机字体排版，字符集伪装、文字映射和引擎绘制以游戏实际结果为准。

垂直度量和字符集伪装需要选择具体字体。400 字重、100% 比例、0 间距表示沿用上游中性设置。点击“应用到游戏”提交完整参数，“停用替换”提交中性配置。中文等本地化名称在通信前转换为字体自己的英文家族名，再由兼容构建验证字体的 Unicode 名称，避免转区前后枚举名称不同。普通中文字体替换自动处理 Shift-JIS 字体能力，不需要手动开启字符集伪装，也不改变原始文本编码；显式源/目标伪装仍按面板选择执行。只在 Hook 接收成功后原子保存该游戏配置，旧配置缺少新增字段时使用中性默认值。

运行中的应用只走热更新链路，不提供关闭游戏重开的替代流程。ACK 仅表示配置已接收并请求刷新，不能证明任意引擎已经重绘；兼容构建仍无法刷新某游戏时，该游戏不满足本功能的即时更新要求。

## 边界

Rust 面板 → 版本化 IPC → C++ SimpleFontHook 兼容构建。

- core 负责参数校验、旧配置默认值、PE 位数识别和通信编码。
- 桌面 font_tools 负责可配置快捷键（默认 Shift+T）、原生控件、预览及异步请求；game_window/game_input 与截图共用。
- 同架构 loader 校验实际进程位数、映像路径、创建时间和 IPC 窗口所属 PID；仅访问被拒绝时提升单次辅助请求。UAC 取消、超时、未知版本和准备字体失败均不保存为成功。
- native/font-hook/compat 集中维护已授权的兼容补丁：运行中安装、Detours 线程登记及 DLL 固定到进程退出；中文字体能力补全；KiriKiri 已知 ABI 的缓存刷新；Artemis/PFS 只读解析和相对字号修正。
- font_picker.cpp 的生命周期由 IPC 消息窗口代替，不创建可见选择器、不注册上游快捷键。字体表算法仍调用上游 FontPatcher，配置发布和通知沿用上游入口。GalGear 按游戏保存参数，兼容构建不读写共享 FontHook.ini。
- 字体副本在游戏进程内准备，完成后才发布参数；失败保留原配置。按字体及度量/伪装参数复用副本，最多 64 个、128 MiB，保留到进程退出，避免旧字体句柄失效。不写字体文件或磁盘资源包。

## 通信与更新

协议 v2 使用消息窗口 GalGear.FontHook.Bridge.v2，标题为十进制 PID。
加载前以 DONT_RESOLVE_DLL_REFERENCES 检查 GalGearFontBridgeV2 导出标识，不执行 DLL 入口。没有标识的官方 DLL 或旧适配版直接拒绝，避免弹出原选择器。

握手消息为 WM_APP + 0x476，响应 0x000200ff；客户端接受 v2 中包含全部必需能力的扩展位。WM_COPYDATA 的 dwData 为 0x47474632。数据包为 128 字节小端：

| 偏移 | 内容 |
| --- | --- |
| 0–15 | version=2、length=128、height_percent、width_percent（u32） |
| 16–79 | UTF-16 字体名，含终止符，共32单元 |
| 80–103 | 字距 i32、行距 i32、字重 u32、垂直开关 u32、上行高度 i32、下行高度 i32 |
| 104–127 | 伪装开关、源字符集、目标字符集、映射模式、回退代码页、保留0（u32） |

映射 0=关闭、1=日文旧字形、2=繁转简、3=简转繁。响应 1=接受并请求刷新、2=上一轮通知尚在进行、3=字体匹配失败、4=字体准备失败、0=拒绝。协议没有地址或平台宽度字段。已接受的请求不自动重试；下一次应用需等待通知完成。上游配置读写并非全量原子快照，本适配不宣称修复了内核并发问题。

```powershell
# 默认使用上次安装记录的提交（首次为已验证提交）；需要 Visual Studio C++ x86/x64 工具集。
.\scripts\build-font-hook.ps1 -Fixtures
# 获取官方 main，并自动构建兼容适配版；不需要重新编译 Rust 面板。
.\scripts\build-font-hook.ps1 -Update -Fixtures
```

每次从 Git 提交导出全新构建目录，不修改 tools/font-hook-source 检出。补丁锚点、PFS 替换边界、编译或未修改内核文件的哈希检查失败时不发布新组件。成功后组件位于 tools/font-hook/x86 和 x64，adapter.json 记录提交、协议、兼容构建版本及内核修改清单（coreUnmodified=false）。下载更新包时替换同架构适配 DLL 与 loader 即可，保持协议 v2 的更新无需改面板；未知版本明确报不兼容。上游改变适配边界时需要维护补丁，不能保证任意未来版本自动兼容。

DLL 加载后由 Windows 保持到目标进程结束，磁盘更新供后续进程使用；这不影响当前进程内的字体参数实时应用。不要在已加载旧适配器的进程里叠加不同版本。

## 验证

```powershell
cargo test -p galgear-core --locked font_tools
cargo test -p galgear --locked font_tools -- --include-ignored --test-threads=1
```

隔离 GDI 夹具验证运行中加载、实际字形像素变化、进程身份与数据包校验；原生面板测试覆盖三语、明暗主题、输入、预览和窗口定位。中文字体兼容夹具检查实际字形家族及 Shift-JIS 字节含义。夹具通过不等同于全部真实引擎兼容通过。真实游戏中仍须观察字体、度量、映射及伪装效果，不以 ACK 代替画面验收。
